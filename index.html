1. Big-O Notation

Big O describes how runtime grows relative to input as input gets arbitrarily large.

Key Rules

1. Drop constants: O(2n) → O(n)
2. Drop less significant terms: O(n² + n) → O(n²)
3. Formal definition: f(n) = O(g(n)) if ∃ constants c > 0, n₀ > 0 such that f(n) ≤ c·g(n) for all n ≥ n₀

Complexity Hierarchy (slowest → fastest)

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(nⁿ)

Big-Θ and Big-Ω

Big-Θ (Theta): Exact bound — f(n) = Θ(g(n)) means f grows at the same rate as g
Big-Ω (Omega): Lower bound — f(n) = Ω(g(n)) means f grows at least as fast as g

Sorted Array Operations (FROM EXAM!)

Given sorted array A of size n with no duplicates, indexing is O(1):
• Maximum value max₁≤t≤n A[t]: O(1) — just return A[n]
• Mean/Average (1/n)Σ A[t]: O(n) — must sum all elements
• Median (n odd): O(1) — return A[(n+1)/2], since sorted, (n-1)/2 elements are strictly smaller

Key Points to Memorize

• Quick Sort worst case O(n²): when pivot is always min/max (sorted input without randomization)
• Merge Sort: Always O(n log n), but needs O(n) extra space
• Heap Sort: O(n log n) ALL cases, O(1) space — better worst case than Quick Sort
• 3-way Quick Sort: Handles many duplicates efficiently
• Median-of-three: Pick median of first/mid/last as pivot for better performance
• Quick sort with median partition: worst case = same as heap sort (n log n)
• Quick sort with random partition: worst case = same as merge sort (n log n expected)
• All tree-based sorts (Merge, Quick, Heap): divide and conquer paradigm

5. Binary Search Trees (BST)

BST Property

For every node: left subtree values < node < right subtree values

Key Terms

Root: Top node (no parent)
Leaf: Node with no children
Height: Longest path from root to leaf
Depth: Distance from root to node
Internal node: Non-leaf node
Subtree: Node + all descendants
Path: Sequence of edges
Balanced: Left & right heights differ ≤ 1

BST Operations

OperationAverageWorst (skewed)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)

BST Search Algorithm

Search(root, key):
    if root is NULL or root.key == key:
        return root
    if key < root.key:
        return Search(root.left, key)
    else:
        return Search(root.right, key)

BST Insertion Algorithm

Insert(root, key):
    if root is NULL:
        return new Node(key)
    if key < root.key:
        root.left = Insert(root.left, key)
    else if key > root.key:
        root.right = Insert(root.right, key)
    return root

BST Deletion — 4 Cases

Case 1 — Leaf: Simply remove the node
Case 2 — One child (left only): Find max of left subtree (m), move m to x's position, delete(m) recursively
Case 3 — One child (right only): Find min of right subtree (m), move m to x's position, delete(m) recursively
Case 4 — Two children: Find max of left subtree (m), move m to x's position, delete(m) recursively
Deletion running time: O(h) where h = height of tree

BST Validate (testBST)

testBST(root):
    if root is NULL: return true
    if root.left != NULL and root.left.key > root.key: return false
    if root.right != NULL and root.right.key < root.key: return false
    return testBST(root.left) AND testBST(root.right)

Building Efficient BST (Median Method)

Repeat median(s):
    M <= median(s)
    Partition s into L(smaller than M), M, R(larger than M)
    Root <= M
    Root.Left <= repeat median on L
    Root.Right <= repeat median on R
→ Insertion time: O(log n) or O(h)

6. Tree Traversals

Two Types

1. Breadth First Traversal (BFS): Level-order, uses a QUEUE
2. Depth First Traversal (DFS): Pre/In/Post-order, uses a STACK

DFS Traversal Algorithms

In-order (Left, Root, Right)

Step 1: Traverse left subtree
Step 2: Visit root
Step 3: Traverse right subtree

→ Gives sorted order for BST!

Pre-order (Root, Left, Right)

Step 1: Visit root
Step 2: Traverse left subtree
Step 3: Traverse right subtree

Post-order (Left, Right, Root)

Step 1: Traverse left subtree
Step 2: Traverse right subtree

8. Heaps & HeapSort

Heap Properties

Max-Heap: Parent ≥ children (root is maximum)
Min-Heap: Parent ≤ children (root is minimum)
Heap is always a complete binary tree

Heap Array Indexing (1-based)

Parent(i) = ⌊i/2⌋  |  Left(i) = 2i  |  Right(i) = 2i + 1

⚡ EXAM: Heap Array Indexing (0-based)

Parent(i) = ⌊(i-1)/2⌋  |  Left(i) = 2i + 1  |  Right(i) = 2i + 2

⚡ EXAM: Heap Index Questions

If heap with largest on top stored in array:
a) Parent of A[9] is A[16] → FALSE. Parent(9) = floor(9/2) = A[4] (1-based)
b) Left child of A[8] is A[17] → TRUE. Left(8) = 2×8+1 = A[17] (0-based)
c) Right child of A[8] is A[17] → depends on indexing
d) Grandparent of A[9] is A[2] → TRUE (1-based: parent(9)=4, parent(4)=2)
e) Grandparent of A[8] is A[4] → depends on indexing

Max Heap Construction (Insert)

Step 1 − Create new node at end
Step 2 − Assign value
Step 3 − Compare with parent
Step 4 − If parent < child, swap
Step 5 − Repeat 3-4 until heap property holds

Max Heap Deletion (Remove Root)

Step 1 − Remove root node
Step 2 − Move last element to root
Step 3 − Compare with children
Step 4 − Swap with LARGER child if needed
Step 5 − Repeat 3-4 until heap property holds

⚡ EXAM: Max-Heap Remove Trace

1. Remove root (20), move last (4) to root: [−, 4, 12, 18, 7, 3, 6]
2. 4 < max child (18), swap: [−, 18, 12, 4, 7, 3, 6]
3. 4 < max child (6), swap: [−, 18, 12, 6, 7, 3, 4]

HeapSort Algorithm

HeapSort(A as array):
    BuildHeap(A)
    for i = n to 1:
        swap(A[1], A[i])
        n = n - 1
        Heapify(A, 1)

BuildHeap(A as array):
    n = elements_in(A)
    for i = floor(n/2) to 1:
        Heapify(A, i)

Heapify(A as array, i as int):
    left = 2i
    right = 2i + 1
    if (left <= n) and (A[left] > A[i]):
        max = left
    else:
        max = i
    if (right <= n) and (A[right] > A[max]):
        max = right
    if (max != i):
        swap(A[i], A[max])
        Heapify(A, max)
HeapSort: O(n log n) for ALL cases (best, average, worst)
Space: O(1) — in-place!
Better worst case than Quick Sort O(n²), but Quick Sort faster in practice

9. Red-Black Trees

Properties (MEMORIZE ALL 3)

1. Every node is either RED or BLACK
2. The root is always BLACK
3. If a node is RED, both its children must be BLACK (no two consecutive reds)

RB-Tree Insertion Algorithm

1. Use BST insert algorithm to add K
2. Color the new node K RED
3. Fix violations (if parent P is red → "double-red" violation)

Fixing Double-Red Violations

Case 1: Parent P is BLACK → No problem, done!

Case 2: Parent P is RED → Check P's sibling S:
  Case 2a: S is BLACK or NULL → RESTRUCTURE (trinode restructuring of K, P, G)
    • Sort K, P, G as A, B, C → B becomes parent (BLACK), A and C become children (RED)
  Case 2b: S is RED → RECOLOR
    • P and S become BLACK, G becomes RED (unless G is root → stays BLACK)
    • May propagate double-red upward → check recursively

All operations: O(log n)

⚡ EXAM: RB-Tree Insert 29

Given tree: 25B(18B, 34R(30B(28R), 36B))

Insert 29 as RED child of 28R → double-red: 29R and 28R
28's parent is 30B, uncle is null/black → Case 2a: RESTRUCTURE
Sort {29, 28, 30} → 28=A, 29=B, 30=C → 29 becomes parent (BLACK)

Result: 25B(18B, 34R(29B(28R, 30R), 36B))

10. Splay Trees

Self-adjusting BST where recently accessed element is moved to root via "Splaying".
Every operation (insert, search, delete) performs splaying.

Six Rotation Types

RotationDescription
ZigSingle right rotation (like AVL right rotation)
ZagSingle left rotation (like AVL left rotation)
Zig-ZigDouble zig — move 2 positions right
Zag-ZagDouble zag — move 2 positions left
Zig-ZagZig then zag — right then left
Zag-ZigZag then zig — left then right

Splay Tree Operations

Insert: BST insert → Splay the newNode to root
Search: BST search → Splay the found node to root
Delete: Splay the node to root → Delete from root → Join remaining subtrees

12. Graph Theory

Key Definitions

Vertex: Node in graph
Edge: Line between two vertices
Adjacent: Two vertices connected by an edge
Path: Sequence of edges between vertices
Degree: Number of edges incident to vertex
Indegree: Edges coming IN (directed graphs)
Outdegree: Edges going OUT (directed graphs)
Distance d(U,V): Shortest path length
Eccentricity e(V): Max distance to any other vertex

Graph Types

TypeDefinition
Non-directedEdges have no direction (ab = ba)
DirectedEdges have direction (ab ≠ ba)
SimpleNo loops, no parallel edges
ConnectedPath exists between every pair of vertices
DisconnectedNot all pairs connected
Complete (Kₙ)Every vertex connects to every other vertex
Cycle Graph (Cₙ)n vertices (n≥3) forming a single cycle; every vertex has degree 2
CyclicContains at least one cycle
AcyclicNo cycles
BipartiteVertices split into two sets V₁, V₂; edges only between sets
Complete BipartiteEvery vertex in V₁ connects to every vertex in V₂

Graph Representations

Adjacency Matrix: n×n matrix, M[i][j] = 1 if edge exists. Space: O(n²)
Adjacency List: Array of linked lists. Space: O(n + e)

Graph Formulas (MEMORIZE!)

Max edges in simple graph with n vertices: n(n−1)/2
Number of simple graphs with n vertices: 2^(n(n−1)/2)
Degree of any vertex in simple graph: deg(v) ≤ n−1
In simple graph with n vertices: max degree ≤ n−1

Complement of Graph

G' has same vertices as G, but edge {U,V} is in G' if and only if it is NOT in G.
G + G' = Complete graph Kₙ

Spanning Trees

A spanning tree is a subset of graph G covering ALL vertices with minimum edges.
• No cycles, cannot be disconnected
• Every connected undirected graph has at least one spanning tree
• A disconnected graph has NO spanning tree

Cut Vertex & Cut Edge

Cut Vertex: Removing it disconnects the graph
Cut Edge (Bridge): Removing it disconnects the graph
• An edge is a cut edge iff it is NOT part of any cycle
• Max cut edges possible: n−1
• When cut edges exist → cut vertices also exist
• When cut vertex exists → cut edge may or may NOT exist

Cut Set

A subset E' of edges whose deletion disconnects graph G. The deleted edges = cut set.

DFS & BFS on Graphs

DFS (Depth-First Search)

Uses: STACK

Rule 1: Visit adjacent unvisited vertex,
  mark visited, push to stack
Rule 2: If no adjacent unvisited,
  pop from stack
Rule 3: Repeat until stack empty

BFS (Breadth-First Search)

Uses: QUEUE

Rule 1: Visit adjacent unvisited vertex,
  mark visited, insert in queue
Rule 2: If no adjacent unvisited,
  remove first vertex from queue
Rule 3: Repeat until queue empty
⚡ DFS same as BFS: Design a graph with ≥5 vertices where DFS = BFS
→ A linear chain: 1-2-3-4-5. Both DFS and BFS give: 1,2,3,4,5
