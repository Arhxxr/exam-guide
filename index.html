Big-O Notation

Big-O notation provides a formal mathematical framework for analyzing algorithm efficiency. It describes how an algorithm's time or space requirements grow as the input size increases.

Formal Definition

A function T(n) is in O(F(n)) if there exist positive constants C and n₀ such that:

T(n) ≤ C · F(n) for all n > n₀

This means that for sufficiently large input sizes, the algorithm's time is bounded above by a constant multiple of F(n).

Simplification Rules

Key Principles

  • Drop Constants: O(5n) = O(n), O(100) = O(1)
  • Drop Lower Order Terms: O(n² + n) = O(n²), O(2n + 5) = O(n)
  • Worst Case Analysis: We typically analyze the worst-case scenario for robustness

Space Complexity

Space complexity uses the same notation to analyze memory usage. Auxiliary space (excluding input) is often the focus. For example:

  • Iterative algorithms with fixed variables: O(1) space
  • Recursive algorithms create a call stack proportional to depth: O(h) space for height h
  • Algorithms that store data structures: O(n) or more depending on structure

Graph Basics & Traversals

Graphs are fundamental data structures consisting of vertices (nodes) and edges connecting them. They model relationships and networks across countless applications.

Key Definitions

Vertex (Node)
A fundamental unit in a graph, representing an entity or point.
Edge
A connection between two vertices. Can be directed (ordered pair) or undirected (unordered pair).
Adjacency
Two vertices are adjacent if there is an edge directly connecting them.
Path
A sequence of vertices where each consecutive pair is connected by an edge. A simple path has no repeated vertices.
Degree
The number of edges incident to a vertex (undirected graphs). In directed graphs: in-degree (incoming edges) and out-degree (outgoing edges).
Distance
The length (number of edges) of the shortest path between two vertices.
Eccentricity
The maximum distance from a vertex to any other vertex in the graph.

Directed vs Undirected

In undirected graphs, edges have no direction: if there's an edge between A and B, we can traverse both A→B and B→A. In directed graphs, edges point in one direction.

Simple Graph

A simple graph has no self-loops and at most one edge between any pair of vertices. The maximum number of edges is n(n-1)/2 for an undirected graph with n vertices.

Graph Representations

Representation Space Complexity Edge Lookup Add Edge Best For
Adjacency Matrix O(V²) O(1) O(1) Dense graphs, checking connections
Adjacency List O(V + E) O(degree) O(1) Sparse graphs, traversals

Depth-First Search (DFS)

DFS explores as far as possible along each branch before backtracking. It uses a stack (explicit or via recursion).

Algorithm Concept

  • Start at a source vertex, mark it as visited
  • Recursively explore each adjacent unvisited vertex
  • Backtrack when no unvisited neighbors remain
  • Result: visits all reachable vertices, builds a DFS tree

Time Complexity: O(V + E) | Space Complexity: O(V) (recursion stack)

Breadth-First Search (BFS)

BFS explores vertices level by level, visiting all neighbors before moving deeper. It uses a queue.

Algorithm Concept

  • Start at a source vertex, enqueue it, mark as visited
  • Dequeue a vertex and explore all its adjacent unvisited neighbors
  • Enqueue all unvisited neighbors, mark them as visited
  • Repeat until queue is empty
  • Result: finds shortest paths in unweighted graphs

Time Complexity: O(V + E) | Space Complexity: O(V) (queue)

Graph Types & Properties

Graphs come in many varieties, each with distinct structural properties that affect algorithm selection and complexity analysis.

Graph Type Classification

Graph Type Definition Key Property
Connected There is a path between every pair of vertices Single component, all vertices reachable
Disconnected At least one pair of vertices has no path between them Multiple connected components
Complete Every pair of distinct vertices has an edge (denoted K_n) Maximum possible edges: n(n-1)/2
Cycle Vertices arranged in a closed loop C_n (n vertices, n edges) Each vertex has degree 2
Cyclic Contains at least one cycle Has feedback, circular dependencies
Acyclic Contains no cycles (a DAG) Allows topological ordering
Bipartite Vertices split into two sets; edges only between sets (never within) Colorable with 2 colors, no odd cycles
Complete Bipartite Bipartite graph where every vertex in set A connects to every vertex in set B (K_{m,n}) m·n edges total

Critical Graph Properties

Spanning Tree
A subgraph that is a tree and includes all vertices of the original graph. Any connected graph with n vertices has a spanning tree with exactly n-1 edges.
Cut Vertex (Articulation Point)
A vertex whose removal increases the number of connected components. Removing it disconnects the graph.
Cut Edge (Bridge)
An edge whose removal increases the number of connected components. Critical for connectivity.
Cut Set
A set of edges whose removal disconnects the graph (increases connected components). The minimum cut set has size equal to the edge connectivity.
Graph Complement
For graph G, the complement Ḡ contains the same vertices but edges are reversed: an edge exists in Ḡ iff it does NOT exist in G.

Session 15: Minimum Spanning Trees

MST Definition

A Minimum Spanning Tree (MST) is a spanning tree of a weighted, connected, undirected graph that has the minimum possible total weight. An MST contains exactly V−1 edges and connects all V vertices without creating any cycles.

Kruskal's Algorithm

Strategy: Sort all edges by weight (ascending), then greedily add the smallest edge that does not create a cycle.

How it works: Using a Union-Find (Disjoint Set Union) data structure, Kruskal's algorithm maintains connected components and only adds an edge if its endpoints are in different components.

KRUSKAL(G):
  A = ∅
  for each v ∈ V: MAKE-SET(v)
  Sort edges by weight (ascending)
  for each edge (u,v) in sorted order:
    if FIND-SET(u) ≠ FIND-SET(v):
      A = A ∪ {(u,v)}
      UNION(u, v)
  return A

Time Complexity: O(E log E) — dominated by sorting edges. With path compression and union by rank, the Union-Find operations are nearly O(1).

Prim's Algorithm

Strategy: Grow the MST from a starting vertex by always adding the minimum-weight edge that crosses from the reached set to the unreached set.

How it works: Maintain two sets: ReachSet (vertices already in MST) and UnReachSet (vertices not yet in MST). At each step, find the minimum-weight edge connecting these sets and add it to the MST.

PRIM(G, start):
  ReachSet = {start}, UnReachSet = V − {start}, MST = ∅
  while UnReachSet ≠ ∅:
    Find min-weight edge (x,y) where x ∈ ReachSet, y ∈ UnReachSet
    MST = MST ∪ {(x,y)}
    ReachSet = ReachSet ∪ {y}
    UnReachSet = UnReachSet − {y}
  return MST

Time Complexity:

  • O((V+E) log V) with a binary heap
  • O(E + V log V) with a Fibonacci heap

Prim's Distance Table Method

Prim's algorithm maintains a distance table for each vertex, tracking the minimum weight of any edge from the ReachSet to that vertex. This table is updated dynamically:

  • Distance: The minimum cost to reach this vertex from the current MST
  • Parent: The vertex in the ReachSet that provides this minimum edge
  • In MST: Whether this vertex has been added to the MST yet

At each iteration, Prim's selects the vertex from UnReachSet with the smallest distance value and adds it to the MST along with the edge from its parent.

Session 16: Shortest Path Algorithms

Problem Variations

Shortest path problems are categorized by their source and destination counts:

  • SSSD (Single-Source, Single-Destination): Find shortest path from one source to one target
  • SSMD (Single-Source, Multiple-Destinations): Find shortest paths from one source to all vertices
  • MSSD (Multiple-Sources, Single-Destination): Find shortest paths from all sources to one target
  • MSMD (Multiple-Sources, Multiple-Destinations): Find shortest paths between all pairs of vertices

Dijkstra's Algorithm

Requirement: All edge weights must be non-negative.

Pseudocode

DIJKSTRA(G, source):
  for each v: dist[v]=∞, prev[v]=null
  dist[source] = 0, Q = all vertices
  while Q ≠ ∅:
    u = vertex in Q with min dist[u]
    remove u from Q
    for each neighbor v of u in Q:
      if dist[u] + w(u,v) < dist[v]:
        dist[v] = dist[u] + w(u,v)
        prev[v] = u
  return dist[], prev[]

Time Complexity: O((V+E) log V) with binary heap

Bellman-Ford Algorithm

Advantages: Handles negative edge weights and detects negative cycles.

Pseudocode

BELLMAN-FORD(V, E, source):
  for each v: dist[v]=∞, pred[v]=null
  dist[source] = 0
  for i = 1 to |V|-1:
    for each edge (u,v,w):
      if dist[u]+w < dist[v]:
        dist[v] = dist[u]+w, pred[v] = u
  for each edge (u,v,w):
    if dist[u]+w < dist[v]: ERROR "Negative cycle"
  return dist[], pred[]

Time Complexity: O(V·E)

Network Flow (Session 17)

Problem Setup

A directed graph G=(V,E) with:

  • Capacity c(u,v) ≥ 0 for each edge (u,v)
  • Source vertex s and sink vertex t
  • Flow f(u,v) representing amount of resource traveling on each edge

Constraints

  • Capacity constraint: f(u,v) ≤ c(u,v)
  • Flow conservation: For all v ≠ s,t: Σ f(u,v) = Σ f(v,w) (inflow = outflow)
  • Skew symmetry: f(u,v) = -f(v,u)

Ford-Fulkerson Algorithm

FordFulkerson(G, s, t):
  for each edge (u,v) in E:
    f(u,v) = 0
    f(v,u) = 0
  while there exists augmenting path p from s to t in residual graph Gf:
    bottleneck = min(c(u,v) - f(u,v)) for (u,v) in p
    for each edge (u,v) in p:
      f(u,v) += bottleneck
      f(v,u) -= bottleneck
  return f

Key Concepts

  • Residual graph Gf: Graph with residual capacities cf(u,v) = c(u,v) - f(u,v)
  • Augmenting path: Path from s to t in Gf with available capacity
  • Bottleneck: Minimum residual capacity along an augmenting path

Max-Flow Min-Cut Theorem

The maximum flow from s to t equals the minimum capacity of any s-t cut.

Ford-Fulkerson Visualization

Dinic's Algorithm

Improved algorithm using level graphs and blocking flows:

Dinic(G, s, t):
  flow = 0
  while there exists augmenting path from s to t in Gf:
    build level graph from Gf using BFS
    while there exists blocking flow in level graph:
      find blocking flow using DFS
      add blocking flow to total flow
  return flow

Time complexity: O(V²E) or O(VE) for unit capacities

Topological Sort & DAGs (Session 21)

Definition

A topological ordering of a directed acyclic graph (DAG) is a linear ordering of vertices such that for every directed edge (u,v), u appears before v in the ordering.

DAG Property

Topological ordering exists if and only if the graph is acyclic (a DAG).

Kahn's Algorithm (BFS-based)

Kahn(G):
  compute in-degree for each vertex
  initialize queue Q with all vertices of in-degree 0
  topo_order = []
  while Q is not empty:
    u = Q.dequeue()
    append u to topo_order
    for each neighbor v of u:
      in-degree[v] -= 1
      if in-degree[v] == 0:
        Q.enqueue(v)
  if |topo_order| != |V|:
    return error "cycle detected"
  return topo_order

Complexity Analysis

  • Time: O(V + E) — each vertex and edge processed once
  • Space: O(V) — for queue and in-degree array

Kahn's Topological Sort Visualization

Critical Path Method

Application of topological sort to project scheduling:

  • Tasks are vertices; dependencies are edges with durations
  • Topologically sort tasks to find critical path (longest path S→T)
  • Critical path determines minimum project completion time
  • Tasks on critical path have zero slack; non-critical tasks can be delayed

Used in project management and PERT analysis.

Algorithm Design Paradigms (Session 18)

Divide & Conquer

Solve a problem by dividing it into independent subproblems, solving each recursively, and combining solutions:

  1. Divide: Break problem into smaller instances
  2. Conquer: Solve subproblems recursively
  3. Combine: Merge solutions of subproblems

Examples:

  • Binary Search: O(log n)
  • Merge Sort: O(n log n)
  • Quick Sort: O(n log n) average, O(n²) worst
  • Strassen's Matrix Multiplication: O(n^2.81)

Greedy Algorithms

At each step, make the locally optimal choice, hoping to find a global optimum:

  1. Define what constitutes a "greedy choice"
  2. Prove that a greedy choice leads to an optimal solution
  3. Show optimal substructure: solution contains optimal solutions to subproblems

Examples:

  • Prim's Algorithm (MST): select minimum edge from frontier
  • Kruskal's Algorithm (MST): select minimum edge not creating cycle
  • Dijkstra's Shortest Path: select minimum unprocessed distance vertex
  • Huffman Coding: repeatedly merge two smallest frequency nodes

Caution: Greedy Doesn't Always Work

Greedy algorithms do not guarantee optimal solutions for all problems. Example: coin change problem with certain denominations, or the traveling salesman problem.

Brute Force

Enumerate all possible solutions and return the best:

  • Simplest approach, often provides baseline for comparison
  • Exponential or polynomial time depending on problem size
  • Useful for small inputs or when optimization is not practical
Project Selection Example

Compare three greedy heuristics and brute force on a project selection problem:

Strategy Selected Projects Total Value
Greedy by Time (shortest first) A, B, E $400K

Process Scheduling: Shortest-Job-First Optimality

Theorem: For single-machine scheduling to minimize average completion time, processing jobs in order of increasing duration is optimal (Shortest Job First).

Proof sketch:

  1. Let jobs be ordered by duration: d₁ ≤ d₂ ≤ ... ≤ dₙ
  2. Average completion time: (d₁ + (d₁+d₂) + (d₁+d₂+d₃) + ... + Σdᵢ) / n
  3. Each job j contributes dⱼ to the completion time of itself and all later jobs: (n-j+1)·dⱼ
  4. Total time: Σ(n-j+1)·dⱼ
  5. To minimize, assign larger coefficients (n-j+1) to smaller durations dⱼ
  6. Therefore, SJF is optimal

Example: Jobs with durations [3, 1, 4, 2] minutes.

  • SJF order [1, 2, 3, 4]: completions at 1, 3, 6, 10 → avg = 5
  • FCFS order [3, 1, 4, 2]: completions at 3, 4, 8, 10 → avg = 6.25

val = (q.y - p.y)·(r.x - q.x) - (q.x - p.x)·(r.y - q.y)
val == 0: Collinear

Polynomial Reduction (≤p)

Definition: Problem A ≤p B if we can solve A using a polynomial-time algorithm for B.

Cost formula: TA(n) = O(f(n)) + O(poly) · TB(poly(n))

Two Uses of Reduction

  1. Algorithm Design: If A ≤p B and B has fast algorithm → fast algorithm for A
  2. Hardness Proof: If A ≤p B and A is hard → B is hard

Reduction Example: Sorting ≤p Convex Hull

To sort array [x₁, x₂, ..., xₙ]:

  1. Map to points: (xᵢ, xᵢ²) on parabola y = x²
  2. Compute convex hull using a CH algorithm
  3. Traverse hull counterclockwise from left → sorted order

Cost: O(n) mapping + O(n log n) CH = O(n log n) sorting ✓

Proving NP-Completeness

Two-step proof to show problem X is NP-Complete:

  1. X ∈ NP: Show a verifier that checks a "yes" certificate in polynomial time
  2. NPC ≤p X: Reduce a known NPC problem to X (e.g., SAT ≤p X)

Once step 2 is done for one NPC, further reductions become easier.

Decision vs Optimization

  • Decision: "Is there a solution with cost ≤ k?" (yes/no) → in NPC
  • Optimization: "Find the minimum cost solution" → typically NP-Hard
  • Example: "Hamiltonian Cycle?" (decision, NPC) vs "TSP" (optimization, NP-Hard)

NP-Complete Problems

Sessions 22 & 23

Clique

Definition: A subset of vertices where every pair is connected by an edge.

Decision Problem: "Does G have a clique of size k?"

  • NP-Complete (reduction from SAT)
  • Naive: O(n^k · k²) check all k-subsets

Two-Clique Test via Complement Bipartiteness

To find two disjoint cliques in G:

  1. Compute complement graph Ḡ (edges reversed)
  2. Check if Ḡ is bipartite using BFS/DFS
  3. If yes: G contains two vertex-disjoint cliques (each partition in Ḡ forms a clique in G)

Time: O(V + E) ✓

Vertex Cover

Definition: A set of vertices such that every edge has at least one endpoint in the set.

Decision Problem: "Does G have a vertex cover of size ≤ k?"

  • NP-Complete
  • 2-Approximation Algorithm: Greedy edge covering

2-Approximation for Vertex Cover

VERTEX_COVER_APPROX(G):
  C = ∅
  E' = copy of E(G)
  while E' ≠ ∅:
    pick any edge (u, v) ∈ E'
    C = C ∪ {u, v}
    remove all edges incident to u or v from E'
  return C

Guarantee: |C| ≤ 2 · OPT (since each picked edge covers ≥2 uncovered edges)

Independent Set

Definition: A set of vertices with no edges between them.

Decision Problem: "Does G have an independent set of size ≥ k?"

  • NP-Hard
  • Complement relationship: IndSet(G, k) ⟺ VertexCover(Ḡ, n-k)
  • No known poly-time approximation (APX-hard)

Hamiltonian Cycle

Definition: A cycle that visits each vertex exactly once and returns to start.

Decision Problem: "Does G have a Hamiltonian cycle?"

  • NP-Complete
  • Naive: Try all (n-1)!/2 permutations → O(n!)
  • Backtracking: Build path incrementally, prune impossible branches

Backtracking Approach

HAM_CYCLE_BT(v, path, visited):
  if len(path) = n:
    if edge(v, start) exists:  // close cycle
      return path + [start]  // found!
    else:
      return FAIL

  for each neighbor u of v:
    if u not in visited:
      visited.add(u)
      result = HAM_CYCLE_BT(u, path + [u], visited)
      if result ≠ FAIL:
        return result
      visited.remove(u)  // backtrack

  return FAIL

Time: Still O(n!) worst-case, but better pruning in practice

Traveling Salesman Problem (TSP)

Definition: Find the shortest cycle visiting all cities exactly once.

Decision Problem: "Is there a tour with cost ≤ k?" (NPC)

Optimization Problem: "Find minimum-cost tour" (NP-Hard)

Naive Approach

Try all (n-1)!/2 permutations: O(n!)

Dynamic Programming Solution

// C[S][i] = min cost to visit all vertices in set S, ending at vertex i
// (assuming we start from vertex 0)

C[{0}][0] = 0
for each set S of size k > 1:
  for each vertex i ∈ S where i ≠ 0:
    C[S][i] = min over j ∈ S-{i}:
              C[S-{i}][j] + dist[j][i]

Answer = min over i ≠ 0:
         C[{0,...,n-1}][i] + dist[i][0]

Time: O(n² · 2ⁿ) — better than O(n!) but still exponential

2-Approximation via MST

  1. Build MST of the graph → cost MST
  2. Preorder walk: Do DFS on MST, visit vertices in order of first encounter
  3. Skip repeated vertices and continue → forms a tour

Guarantee: Tour cost ≤ 2 · MST cost ≤ 2 · OPT (requires triangle inequality)

Proof sketch: MST ≤ OPT, preorder walk ≤ 2·MST (each MST edge traversed ≤2 times)

Approximation Algorithms

Why Approximation?

NP-Hard problems have no known polynomial-time exact solution (unless P=NP). Instead, we seek solutions that are provably close to optimal.

HW1 Q1: Missing Number

Problem: Given array of n-1 integers from 1 to n, find the missing one. O(n) time, O(1) space.

Solution

Approach: Use sum formula.

FIND_MISSING(arr):
  n = len(arr) + 1
  expected_sum = n * (n + 1) / 2
  actual_sum = sum(arr)
  return expected_sum - actual_sum

Time: O(n) | Space: O(1)

Why it works: Sum of 1..n minus sum of array elements = missing number.

HW1 Q2: Pairs with Sum

Problem: Count pairs of integers with a target sum.

Solution

COUNT_PAIRS(arr, target):
  count = 0
  for i = 0 to len(arr) - 2:
    for j = i + 1 to len(arr) - 1:
      if arr[i] + arr[j] = target:
        count = count + 1
  return count

Time: O(n²) | Space: O(1)

Optimization: Use hash set for O(n) time (one pass)

AVL Rotations Summary

  • Single Left Rotation: Right-heavy unbalanced tree
  • Single Right Rotation: Left-heavy unbalanced tree
  • Left-Right Rotation: Left child, then right rotation on parent
  • Right-Left Rotation: Right child, then left rotation on parent

Invariant: |height(left) - height(right)| ≤ 1 at every node

Red-Black Tree Operations

All operations (search, insert, delete) are O(log n) with at most 3 rotations per insertion/deletion. Maintains balance without strict height requirement of AVL.

NP Quick Reference

  • P: Polynomial time solvable
  • NP: Polynomial time verifiable
  • NP-Complete: Hardest in NP, all NP reduces to it (e.g., SAT, 3-SAT, Clique, VC)
  • NP-Hard: At least as hard as NP (may not be in NP, e.g., TSP optimization)
  • Assumption: P ≠ NP → NPC unsolvable in poly time
  • Proof Recipe: (1) Show in NP, (2) reduce known NPC

Key Formulas

  • Approximation ratio: ALG / OPT ≤ constant (e.g., 2 for VC)
