Problem 1.2 — Dijkstra Fails: Negative Weights~8 pts

Consider this graph with a negative edge:

Edges: A → B : 1 A → C : 5 B → C : -4

(a) Trace Dijkstra's algorithm from source A. What shortest distance does it compute for C?

(b) What is the ACTUAL shortest distance from A to C? Explain why Dijkstra fails here.

I've attempted this on paper
(a) Dijkstra's trace:

Step | Pick | Visited | d[A] | d[B] | d[C]
─────┼──────┼─────────┼──────┼──────┼──────
Init |  —   | {}      |  0   |  ∞   |  ∞
  1  |  A   | {A}     |  0   |  1   |  5     ← B=0+1=1, C=0+5=5
  2  |  B   | {A,B}   |  0   |  1   | -3     ← C=min(5, 1+(-4))=-3
  3  |  C   | {A,B,C} |  0   |  1   | -3

Dijkstra computes: dist[C] = -3

(b) Actual shortest distance:
Path A → B → C = 1 + (-4) = -3
Path A → C = 5

Actual shortest = -3. In THIS particular case, Dijkstra happens to get the right answer!

BUT here's where it typically fails — consider a modified graph:

A → B : 4
A → C : 3
B → C : -2

Dijkstra trace:
  Step 1: Pick A. d[B]=4, d[C]=3.
  Step 2: Pick C (d=3, smaller). Mark C as VISITED. d[C]=3 is "locked in."
  Step 3: Pick B. Try to update C: d[B]+w(B,C) = 4+(-2) = 2 < 3.
  But C is already visited! Dijkstra SKIPS this update.
  Dijkstra says dist[C] = 3. Actual shortest = A→B→C = 4+(-2) = 2.

Why Dijkstra fails:
Dijkstra's correctness relies on the GREEDY PROPERTY: once a vertex is
"visited" (extracted from the priority queue), its distance is final.
This only works when all edge weights are non-negative, because a visited
vertex can never have its distance improved by going through an unvisited one.

With negative edges, a visited vertex CAN be improved later, violating
the greedy assumption. Use Bellman-Ford instead for negative weights.

Problem 2.3 — Kruskal vs Prim Conceptual~5 pts

(a) Can Kruskal's and Prim's produce different MSTs on the same graph? Under what conditions?

(b) When would you prefer Kruskal's over Prim's, and vice versa? State the time complexities for each.

(c) How many edges does any spanning tree of a graph with n vertices have? Why?

I've attempted this on paper
(a) Can they produce different MSTs?
Yes, but ONLY when the graph has edges with EQUAL (tied) weights.
If all edge weights are distinct, both algorithms produce the EXACT same MST.
With ties, different tie-breaking choices can lead to different spanning trees,
but all will have the same TOTAL weight (they're all minimum).

(b) When to prefer each:
Kruskal's: O(E log E) — better for SPARSE graphs (E ≪ V²)
  Uses Union-Find. Edge-centric: sorts edges and processes them.

Prim's: O(V²) with array, O((V+E) log V) with min-heap
  Better for DENSE graphs (E ≈ V²) with array implementation.
  Vertex-centric: grows MST from a single vertex.

(c) Spanning tree edge count:
A spanning tree of n vertices always has exactly n - 1 edges.
Why: A tree is a connected acyclic graph. Starting with n isolated vertices,
each edge connects two components (reducing component count by 1).
To go from n components to 1 component requires exactly n-1 edges.

Problem 4.2 — Max-Flow Min-Cut Conceptual~5 pts

(a) State the Max-Flow Min-Cut Theorem.

(b) After running Ford-Fulkerson, how do you find the minimum cut?

(c) Why must we include backward edges in the residual graph? What goes wrong without them?

I've attempted this on paper
(a) Max-Flow Min-Cut Theorem:
In any flow network, the value of the maximum flow equals the capacity
of the minimum cut. A cut (S,T) partitions vertices into S (containing
source) and T (containing sink). Cut capacity = sum of capacities of
edges going from S to T.

(b) Finding the minimum cut:
After Ford-Fulkerson terminates (no augmenting path exists):
1. Run BFS/DFS from source s in the FINAL residual graph
2. Let S = set of vertices reachable from s
3. Let T = V \ S (everything else, including t)
4. The min cut = all edges (u,v) in the ORIGINAL graph where u ∈ S and v ∈ T
5. The min cut capacity = sum of these edges' original capacities

(c) Why backward edges are necessary:
Backward edges in the residual graph represent the ability to "undo" flow
that was previously sent. Without them, the algorithm can get stuck at a
suboptimal solution.

Example: Imagine a network where the first augmenting path sends flow
through an edge that "blocks" a better routing. Backward edges allow a
later iteration to effectively reroute that flow.

Without backward edges: Ford-Fulkerson may produce a flow strictly less
than the maximum flow. The algorithm would terminate prematurely because
it can't find augmenting paths, even though better flow assignments exist.

Problem 5.1 — Complexity Class Definitions~10 pts

(a) Define P, NP, NP-Hard, and NP-Complete. One sentence each.

(b) What is the relationship between P and NP? Is P ⊆ NP, P = NP, or neither? Explain.

(c) True or False (with justification):

  • i. "NP stands for 'not polynomial.'"
  • ii. "Every NP-Hard problem is NP-Complete."
  • iii. "If P = NP, then every NP-Complete problem can be solved in polynomial time."
  • iv. "Sorting is in NP."
I've attempted this on paper
(a) Definitions:
P: The class of decision problems solvable by a deterministic Turing
   machine in polynomial time.

NP: The class of decision problems where a given solution (certificate)
   can be VERIFIED by a deterministic Turing machine in polynomial time.

NP-Hard: A problem H is NP-Hard if every problem in NP can be reduced
   to H in polynomial time (H is at least as hard as anything in NP).

NP-Complete: A problem is NP-Complete if it is both in NP AND NP-Hard
   (the hardest problems that are still in NP).

(b) Relationship:
P ⊆ NP. Every problem solvable in polynomial time is also verifiable
in polynomial time (if you can compute the answer, you can certainly
verify a given answer). Whether P = NP is the most famous open problem
in computer science — it's unknown as of now.

(c) True/False:

i. FALSE. NP stands for "Nondeterministic Polynomial time." It means
   a nondeterministic Turing machine can solve it in polynomial time,
   which is equivalent to saying a deterministic machine can VERIFY
   a solution in polynomial time. NOT "not polynomial."

ii. FALSE. NP-Hard problems might not be in NP. Example: the Halting
    Problem is NP-Hard but not in NP (it's undecidable — you can't even
    verify a solution). NP-Complete = NP-Hard ∩ NP.

iii. TRUE. If P = NP, then NP = P, and since NP-Complete problems are
     in NP, they would be in P, meaning they could all be solved in
     polynomial time.

iv. TRUE. Sorting is in P (e.g., merge sort O(n log n)). Since P ⊆ NP,
    sorting is also in NP. You can verify a sorted array in O(n) by
    checking each consecutive pair — that's a polynomial-time verifier.
Problem 5.2 — NP-Complete Proof: Clique~15 pts

The Clique problem: Given an undirected graph G = (V,E) and an integer k, does G contain a complete subgraph (clique) of size k?

(a) Show that Clique is in NP.

(b) Given that 3-SAT is known to be NP-Complete, outline the key idea of why Clique is NP-Hard. (You don't need to give the full formal reduction from 3-SAT — just explain the high-level approach and why it works.)

(c) Show how to reduce Clique to Independent Set. Prove correctness of your reduction.

I've attempted this on paper
(a) Clique ∈ NP:
Certificate: A set S of k vertices.
Verifier:
  1. Check |S| = k → O(1)
  2. For every pair (u,v) where u,v ∈ S, check that edge (u,v) ∈ E
     → O(k²) ≤ O(V²) checks, each O(1) with adjacency matrix
  Total: O(V²) = polynomial ✓
If all pairs are edges → accept. Otherwise → reject.
Therefore Clique ∈ NP ✓

(b) Why Clique is NP-Hard (high-level 3-SAT → Clique reduction):
Given a 3-SAT formula with m clauses, construct a graph G where:
  - Create one vertex for each literal in each clause (so 3m vertices)
  - Add an edge between two vertices IF:
    (1) They are in DIFFERENT clauses, AND
    (2) They are not contradictory (x and ¬x cannot be connected)
  - Set k = m (number of clauses)

Key insight: A clique of size m in G corresponds to selecting one
satisfying literal from each clause — which is exactly a satisfying
assignment for the 3-SAT formula. The "no contradiction" edge rule
ensures consistency (can't pick both x and ¬x).

This is polynomial: O(m²) to construct the graph.
3-SAT satisfiable ↔ G has clique of size m.
Since 3-SAT is NP-Complete → Clique is NP-Hard ✓

(c) Reduce Clique to Independent Set:
Reduction: Given Clique instance (G, k), create IS instance (Ḡ, k) where:
  Ḡ = complement graph of G
  (edge (u,v) ∈ Ḡ iff (u,v) ∉ G, and vice versa)
  k stays the same.

Construction time: O(V²) to build complement → polynomial ✓

Correctness (→):
Suppose G has a clique C of size k.
In C, every pair of vertices has an edge in G.
In Ḡ, every pair of vertices in C has NO edge (complement).
Therefore C is an independent set of size k in Ḡ. ✓

Correctness (←):
Suppose Ḡ has an independent set I of size k.
In I, no pair of vertices has an edge in Ḡ.
In G, every pair of vertices in I HAS an edge (complement).
Therefore I is a clique of size k in G. ✓

G has clique of size k ↔ Ḡ has IS of size k. Reduction is polynomial. ✓
Problem 5.3 — Reduction: Hamiltonian Cycle → TSP~10 pts

(a) Define the Hamiltonian Cycle problem and the Traveling Salesman Problem (decision version).

(b) Prove that TSP is NP-Complete by reducing from Hamiltonian Cycle. Show both directions of correctness.

I've attempted this on paper
(a) Definitions:
Hamiltonian Cycle (HC): Given a graph G = (V,E), does there exist a
cycle that visits every vertex exactly once and returns to the start?

TSP (decision version): Given a complete weighted graph G = (V,E,w)
and a budget B, does there exist a Hamiltonian cycle with total
edge weight ≤ B?

(b) Proof that TSP is NP-Complete:

Step 1: TSP ∈ NP
Certificate: A permutation of vertices (proposed tour).
Verifier:
  1. Check it visits all V vertices exactly once → O(V)
  2. Check each consecutive edge exists and sum weights → O(V)
  3. Check total weight ≤ B → O(1)
  Total: O(V) = polynomial ✓

Step 2: HC ≤_p TSP (reduce Hamiltonian Cycle to TSP)

Reduction: Given HC instance G = (V,E), construct TSP instance:
  - Create complete graph G' on the same V vertices
  - Assign edge weights:
      w(u,v) = 1  if (u,v) ∈ E  (edge exists in original)
      w(u,v) = 2  if (u,v) ∉ E  (edge doesn't exist)
  - Set budget B = |V|

Construction time: O(V²) to build complete graph → polynomial ✓

Correctness (→):
If G has a Hamiltonian cycle H, then H uses V edges, all in E.
In G', each of these edges has weight 1.
Total tour cost = V × 1 = |V| = B. ✓
So TSP instance has a tour of cost ≤ B.

Correctness (←):
If G' has a Hamiltonian tour of cost ≤ B = |V|:
  The tour uses exactly |V| edges.
  Each edge weighs either 1 or 2.
  Total ≤ |V| with |V| edges → every edge must weigh 1.
  Edges with weight 1 are exactly the edges in original E.
  Therefore the tour uses only edges from E → it's a Hamiltonian cycle in G. ✓

HC has solution ↔ TSP has solution. TSP ∈ NP and HC ≤_p TSP → TSP is NP-Complete. ∎
Problem 5.4 — Approximation Algorithms~8 pts

(a) Describe the 2-approximation algorithm for Vertex Cover. Why does it guarantee a cover at most twice the optimal size?

(b) Describe the 2-approximation algorithm for Metric TSP (with triangle inequality). What role does the MST play?

(c) Why can't we have a constant-factor approximation for general TSP (without triangle inequality)?

I've attempted this on paper
(a) 2-Approx Vertex Cover:
Algorithm:
  1. C = ∅ (empty cover)
  2. While there are uncovered edges:
     - Pick any uncovered edge (u,v)
     - Add BOTH u and v to C
     - Remove all edges incident to u or v
  3. Return C

Why 2-approximation:
  Let M = set of edges picked. These edges are a MATCHING (no shared vertices).
  |C| = 2|M|.
  The optimal vertex cover OPT must include at least one endpoint of each
  edge in M (since they share no vertices, OPT ≥ |M|).
  Therefore |C| = 2|M| ≤ 2·OPT. ✓

(b) 2-Approx Metric TSP:
Algorithm (requires triangle inequality: w(a,c) ≤ w(a,b) + w(b,c)):
  1. Find MST of the graph (cost ≤ OPT, since removing one edge from
     optimal tour gives a spanning tree)
  2. Double every MST edge → Eulerian circuit (cost = 2 × MST ≤ 2·OPT)
  3. Shortcut repeated vertices (go directly, skipping visited ones)
     Triangle inequality guarantees shortcuts don't increase cost.
  Result: tour cost ≤ 2·MST ≤ 2·OPT ✓

(c) Why no constant approximation for general TSP:
Without triangle inequality, there is NO polynomial-time constant-factor
approximation for TSP (unless P = NP).

Proof sketch: If such an approximation existed with ratio c, we could
use it to solve Hamiltonian Cycle:
  - Set edges in E to weight 1, missing edges to weight c·n + 1
  - If HC exists: optimal tour = n. Approximation ≤ c·n.
  - If HC doesn't exist: any tour uses a heavy edge → cost > c·n.
  - The approximation distinguishes these cases → solves HC in poly time.
  Since HC is NP-Complete, this is impossible unless P = NP.

Problem 6.3 — Closest Pair Conceptual~8 pts

(a) Describe the divide-and-conquer algorithm for finding the closest pair of points. Include the key "strip" optimization.

(b) Why do we only need to check the next 7 points in the strip (sorted by y)?

(c) What is the time complexity and why?

I've attempted this on paper
(a) Algorithm:
1. Sort all n points by x-coordinate.
2. Base case: if ≤ 3 points, find closest pair by brute force.
3. Divide: split points into left half L and right half R at the median x.
4. Conquer: recursively find closest pair in L (distance δ_L) and R (distance δ_R).
5. Let δ = min(δ_L, δ_R).
6. STRIP CHECK:
   - Find all points within distance δ of the dividing line (the "strip")
   - Sort strip points by y-coordinate
   - For each point p in the strip, compare p with the next 7 points
     in the y-sorted order
   - If any distance < δ, update δ
7. Return δ (and the corresponding pair).

(b) Why only 7 points?
Consider a strip of width 2δ (δ on each side of the dividing line).
For any point p, we only need to check points within vertical distance δ
(otherwise the total distance > δ, which can't be closer).

This creates a rectangle of width 2δ and height δ. In such a rectangle,
at most 8 points can exist with pairwise distance ≥ δ (think of packing
circles of radius δ/2). So excluding p itself, at most 7 other points
need to be checked.

This constant-bounded check means the strip step is O(n), not O(n²).

(c) Time complexity: O(n log n)
- Sorting by x: O(n log n) once
- Recurrence: T(n) = 2T(n/2) + O(n)
  - 2T(n/2): two recursive calls on halves
  - O(n): building the strip + checking 7 neighbors each
- By Master Theorem: a=2, b=2, f(n)=O(n), log_2(2)=1
  f(n) = Θ(n^1) → Case 2 → T(n) = Θ(n log n)

If we sort by y in each recursion: O(n log n) per level → T(n) = O(n log²n).
Optimization: pre-sort by y once → O(n log n) total.

(a) State the formal definition of f(n) = O(g(n)).

f(n) = O(g(n)) if and only if there exist constants c > 0 and n₀ > 0
such that f(n) ≤ c · g(n) for all n ≥ n₀.

(b) Prove 3n² + 5n = O(n²):
We need to find c > 0 and n₀ > 0 such that 3n² + 5n ≤ c · n² for all n ≥ n₀.

For n ≥ 1:  5n ≤ 5n²  (since n ≤ n² when n ≥ 1)
So: 3n² + 5n ≤ 3n² + 5n² = 8n²

Choose c = 8, n₀ = 1.
Then 3n² + 5n ≤ 8n² for all n ≥ 1. ✓
Therefore 3n² + 5n = O(n²). ∎

(c) Prove n² ≠ O(n):
By contradiction. Assume n² = O(n).
Then ∃ c > 0, n₀ > 0 such that n² ≤ c · n for all n ≥ n₀.
Dividing both sides by n (positive): n ≤ c for all n ≥ n₀.
But this is impossible — n grows without bound, so for n > c, we get n > c.
Contradiction. Therefore n² ≠ O(n). ∎

(c) Kruskal's Algorithm

(d) Closest Pair of Points

I've attempted this on paper
(a) Dijkstra's — GREEDY
Always picks the unvisited vertex with minimum distance (locally optimal
choice). The greedy choice is provably correct because all edge weights
are non-negative.

(b) Merge Sort — DIVIDE & CONQUER
Divides array in half, recursively sorts each half, then merges.
Classic D&C: divide → conquer (recurse) → combine (merge).

(c) Kruskal's — GREEDY
Sorts edges by weight and greedily picks the smallest edge that doesn't

(d) Closest Pair of Points — DIVIDE & CONQUER
Divides points by x-coordinate, recursively finds closest in each half,
then combines by checking the strip. Classic D&C structure.

(e) Bellman-Ford — DYNAMIC PROGRAMMING (relaxation-based)
Iteratively relaxes all edges V-1 times, building up optimal solutions
from shorter paths to longer paths. It's not greedy (doesn't make
irrevocable choices) and not D&C (doesn't divide the problem).
Sometimes classified as "iterative relaxation" or "edge-based DP."
