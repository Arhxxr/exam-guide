HOUR 3 · 45 min
Big-O + Graph Basics — The Foundation Points
WHY: These are pure memorization/recall questions. No tracing, no proofs — just definitions and facts. Guaranteed points if you know them. Free points if you don't overthink.
  • Big-O Hierarchy: 1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n! — Memorize this sequence cold.
  • Formal Definition: f(n) = O(g(n)) iff ∃ c > 0, n₀ > 0 such that f(n) ≤ c·g(n) for all n ≥ n₀. Also Ω (≥) and Θ (both).
  • Simplification: Drop constants (5n² → n²), keep dominant term (n³ + n² → n³), log bases don't matter in Big-O.
  • Adjacency Matrix: O(V²) space. Check edge in O(1). Good for dense graphs.
  • Adjacency List: O(V+E) space. Iterate neighbors in O(degree). Good for sparse graphs.
  • BFS: Queue-based, O(V+E), level-order traversal, shortest path in unweighted graphs.
  • DFS: Stack/recursion, O(V+E), goes deep first, used for: cycle detection, topological sort, connected components, cut vertices.
  • Graph Types: Directed/undirected, weighted/unweighted, DAG, bipartite, complete (K_n), connected/disconnected.
  • Tree Facts: |E| = |V| - 1, connected, acyclic. Any 2 of these 3 properties imply the 3rd.
  • Cut vertex: removal disconnects graph. Bridge: edge whose removal disconnects graph.
HOUR 4 · 60 min
NP-Completeness — Deep Dive (Not Just Memorization)
WHY: This is the #1 topic students lose points on because they memorize definitions without understanding the LOGIC. With 60 minutes (vs 45 in the 6-hr plan), you can actually internalize the reduction framework.
  • P: Problems solvable in polynomial time. Sorting, shortest path, MST — all in P.
  • NP: Problems whose solutions can be VERIFIED in polynomial time. NOT "not polynomial." Every P problem is also NP (P ⊆ NP).
  • NP-Hard: At least as hard as any NP problem. Might not even be in NP (e.g., Halting Problem).
  • NP-Complete: In NP AND NP-Hard. The hardest problems IN NP. Solve any one in poly time → P = NP.
  • Reduction: To prove X is NP-Complete: (1) show X ∈ NP (give poly-time verifier), (2) reduce KNOWN NP-Complete → X in poly time.
  • Practice the proof: Read B3's worked example (IS is NP-Complete via Clique reduction). Then close it and write the proof from memory.
  • Key relationships: Clique in G = Independent Set in complement(G). IS of size k ↔ Vertex Cover of size n-k.
  • Approximation Algorithms: 2-approx Vertex Cover (greedily pick edges). 2-approx TSP with triangle inequality.
  • Decision vs Optimization: Decision = yes/no ("is there a tour of cost ≤ k?"). Optimization = find the best ("find shortest tour"). Decision version is used for NP-Complete proofs.
EXAM TRAP: Reduction direction matters! You reduce FROM the known hard problem TO the new one. "If I could solve NEW in poly time, I could solve KNOWN in poly time." If you get the direction backwards, you prove nothing.
HOUR 5 · 60 min
Network Flow + Bellman-Ford — The Tricky Algorithms
WHY: Ford-Fulkerson has the most steps of any algorithm on this exam (augmenting paths + residual updates + max-flow min-cut). Bellman-Ford is simpler but has subtleties with negative cycles. Both need dedicated attention.
  • Ford-Fulkerson Mechanics: (1) Find augmenting path s→t in residual graph. (2) Find bottleneck = min residual capacity on path. (3) Update: subtract bottleneck from forward edges, ADD to backward edges. (4) Repeat until no path exists.
  • Residual Graph: Forward edge residual = capacity − flow. Backward edge residual = current flow (allows "undoing"). Both must be tracked.
  • Max-Flow Min-Cut: After algorithm terminates, find all vertices reachable from source in residual graph = set S. Unreachable = set T. Min cut = edges from S to T in original graph. Cut capacity = max flow.
  • Edmonds-Karp: Ford-Fulkerson but always use BFS for augmenting path. Guarantees O(VE²). Always terminates.
  • Dinic's: Build level graph via BFS, find blocking flow via DFS, repeat. O(V²E). Faster in practice.
  • Bellman-Ford: Initialize dist[s]=0, all others ∞. Repeat V-1 times: for EVERY edge (u,v,w), relax: if dist[u]+w < dist[v], update.
  • Negative Cycle Detection: Run one MORE iteration (Vth). If ANY edge still relaxes → negative cycle exists → shortest path undefined.
  • Dijkstra vs Bellman-Ford: Dijkstra = O((V+E)log V) but NO negative weights. Bellman-Ford = O(VE) but handles negatives.
PRACTICE: Trace Bellman-Ford on a small graph with a negative edge (but no negative cycle). Verify no edge relaxes on the Vth iteration.
HOUR 6 · 45 min
Geometric Algorithms — The Detail-Heavy Topic
WHY: These algorithms have specific formulas and steps that you MUST get right. The orientation test is used in almost every geometric algorithm. Graham Scan is the most likely exam question here.
  • Orientation Test: For points p1, p2, p3: val = (p2.x−p1.x)(p3.y−p1.y) − (p2.y−p1.y)(p3.x−p1.x). Positive → CCW. Negative → CW. Zero → Collinear.
  • Graham Scan (O(n log n)): (1) Find lowest-y point (leftmost if tie) = anchor. (2) Sort remaining by polar angle from anchor. (3) Push first 3 to stack. (4) For each remaining point: while top-2 and new point make CW turn → pop. Then push new point.
  • Jarvis March / Gift Wrapping (O(nh)): Start from leftmost point. At each step, pick the most counterclockwise point from current. Repeat until back to start. h = number of hull points.
  • Closest Pair (O(n log n)): Sort by x. Divide into left/right. Recursively find closest in each (δ_L, δ_R). δ = min(δ_L, δ_R). Check strip of width 2δ around midline — for each point, compare with next 7 points sorted by y.
  • Point-in-Polygon: Cast ray rightward from point. Count intersections with polygon edges. Odd = inside. Even = outside.
PRACTICE: Do Problem 4 in Section B7 — trace Graham Scan on 7 points. Calculate at least 3 orientation tests by hand to make sure you have the formula right.
HOUR 7 · 45 min
Topological Sort + Design Paradigms + Master Theorem
WHY: Kahn's algorithm is straightforward to trace and likely on the exam. Design paradigms and Master theorem are smaller topics but could be easy points. Don't leave them on the table.
  • Kahn's Topological Sort (O(V+E)): (1) Compute in-degree of all vertices. (2) Add all in-degree 0 to queue. (3) While queue not empty: dequeue u, add to ordering, for each neighbor v: decrease in-degree[v], if 0 → enqueue. (4) If ordering has fewer than V vertices → cycle exists.
  • Critical Path Method: Longest path in DAG. Use topological order, relax edges but MAXIMIZE instead of minimize.
  • Greedy: Make locally optimal choice at each step. Works when: greedy-choice property (local optimal → global optimal) + optimal substructure. Examples: activity selection (sort by finish time), fractional knapsack.
  • Greedy FAILS: 0/1 knapsack (need DP), some graph coloring, coin change with arbitrary denominations.
  • Divide & Conquer: Split → solve subproblems recursively → combine. Examples: merge sort, closest pair, binary search, quicksort.
  • Master Theorem: T(n) = aT(n/b) + f(n). Case 1: f(n) = O(n^(log_b(a)−ε)) → Θ(n^log_b(a)). Case 2: f(n) = Θ(n^log_b(a)) → Θ(n^log_b(a) · log n). Case 3: f(n) = Ω(n^(log_b(a)+ε)) and regularity → Θ(f(n)).
  • Common recurrences: T(n)=2T(n/2)+O(n) → O(n log n) [merge sort]. T(n)=T(n/2)+O(1) → O(log n) [binary search]. T(n)=2T(n/2)+O(1) → O(n) [tree traversal].

B2: Algorithm Step-by-Step Cheatsheets

The EXACT steps to trace on the exam + worked examples. Memorize the format.

Dijkstra's Algorithm — Shortest Path (No Negative Weights)
INPUT: Weighted graph G, source vertex s
OUTPUT: Shortest distances dist[], parent pointers parent[]

1. Initialize: dist[s] = 0, dist[v] = ∞ for all v ≠ s
   parent[v] = null for all v
2. unvisited = {all vertices}
3. While unvisited is not empty:
   a. Pick u ∈ unvisited with MINIMUM dist[u]
   b. Remove u from unvisited (mark as visited)
   c. For each neighbor v of u where v is unvisited:
      if dist[u] + weight(u,v) < dist[v]:
          dist[v] = dist[u] + weight(u,v)
          parent[v] = u
4. Return dist[], parent[]

Worked Example: Graph with 5 vertices

Edges: A→B:4, A→C:1, B→D:1, C→B:2, C→D:5, D→E:3. Source = A.

Step | Pick | Visited      | d[A] | d[B] | d[C] | d[D] | d[E] | Updated
─────┼──────┼──────────────┼──────┼──────┼──────┼──────┼──────┼────────
Init |  —   | {}           |  0   |  ∞   |  ∞   |  ∞   |  ∞   |  —
  1  |  A   | {A}          |  0   |  4   |  1   |  ∞   |  ∞   | B=4,C=1
  2  |  C   | {A,C}        |  0   |  3   |  1   |  6   |  ∞   | B=3,D=6
  3  |  B   | {A,C,B}      |  0   |  3   |  1   |  4   |  ∞   | D=4
  4  |  D   | {A,C,B,D}    |  0   |  3   |  1   |  4   |  7   | E=7
  5  |  E   | {A,C,B,D,E}  |  0   |  3   |  1   |  4   |  7   | —

Shortest paths: A→A=0, A→C→B=3, A→C=1, A→C→B→D=4, A→C→B→D→E=7
⚠️ FAILS with negative edge weights. Use Bellman-Ford instead. Dijkstra's greedy assumption breaks when a "shortcut" through a negative edge is missed.
Prim's Algorithm — Minimum Spanning Tree
INPUT: Weighted undirected graph G
OUTPUT: MST edge set

1. Pick any starting vertex s. MST_set = {s}
2. key[s] = 0, key[v] = ∞ for all v ≠ s, parent[v] = null
3. While MST_set doesn't contain all vertices:
   a. Pick vertex u NOT in MST_set with minimum key[u]
   b. Add u to MST_set
   c. For each edge (u,v,w) where v NOT in MST_set:
      if w < key[v]:
          key[v] = w
          parent[v] = u
4. MST edges = {(parent[v], v) for all v ≠ s}

Worked Example: 5 vertices, starting from A

Edges: A-B:4, A-C:1, B-C:2, B-D:5, C-D:8, D-E:3.

Step | Pick | MST Set      | key[A] | key[B] | key[C] | key[D] | key[E] | Edge Added
─────┼──────┼──────────────┼────────┼────────┼────────┼────────┼────────┼──────────
Init |  —   | {}           |   0    |   ∞    |   ∞    |   ∞    |   ∞    |    —
  1  |  A   | {A}          |   0    |   4    |   1    |   ∞    |   ∞    |    —
  2  |  C   | {A,C}        |   0    |   2    |   1    |   8    |   ∞    |   A-C(1)
  3  |  B   | {A,C,B}      |   0    |   2    |   1    |   5    |   ∞    |   C-B(2)
  4  |  D   | {A,C,B,D}    |   0    |   2    |   1    |   5    |   3    |   B-D(5)
  5  |  E   | {A,C,B,D,E}  |   0    |   2    |   1    |   5    |   3    |   D-E(3)

MST edges: A-C(1), C-B(2), B-D(5), D-E(3). Total weight = 11.
✓ Good for dense graphs (O(V²) with array). Same MST result as Kruskal's, different build order.
Kruskal's Algorithm — Minimum Spanning Tree
INPUT: Weighted undirected graph G with E edges and V vertices
OUTPUT: MST edge set

1. Sort ALL edges by weight (ascending)
2. Initialize Union-Find: each vertex in its own set (parent[v]=v, rank[v]=0)
3. mst_edges = []
4. For each edge (u, v, w) in sorted order:
   if find(u) ≠ find(v):       // different components
       mst_edges.add((u,v,w))
       union(u, v)             // merge components
   else:
       skip                    // would create cycle
5. Stop when |mst_edges| = V-1
6. Return mst_edges

Union-Find operations:
  find(x): follow parent pointers to root (with path compression)
  union(x,y): attach smaller-rank tree under larger-rank root

Worked Example: 4 vertices

Edges: A-B:4, A-C:1, B-C:2, B-D:5, C-D:3.

Sorted edges: A-C(1), B-C(2), C-D(3), A-B(4), B-D(5)

Edge  | Wt | find(u) | find(v) | Action | Reason               | MST so far
──────┼────┼─────────┼─────────┼────────┼──────────────────────┼──────────
A-C   |  1 |    A    |    C    |  ADD   | Different components  | {A-C}
B-C   |  2 |    B    |    A*   |  ADD   | Different components  | {A-C, B-C}
C-D   |  3 |    A*   |    D    |  ADD   | Different components  | {A-C, B-C, C-D}
A-B   |  4 |    A    |    A    |  SKIP  | Same component (cycle)| —
B-D   |  5 |    A    |    A    |  SKIP  | Same component (cycle)| —
*after union

MST edges: A-C(1), B-C(2), C-D(3). Total = 6. V-1 = 3 edges. ✓
✓ Good for sparse graphs. Exactly V-1 edges in any MST. If graph is disconnected, gives MSF (minimum spanning forest).
Ford-Fulkerson / Edmonds-Karp — Maximum Flow
INPUT: Directed graph G with source s, sink t, capacities c(u,v)
OUTPUT: Maximum flow value

1. Initialize: flow(u,v) = 0 for all edges
2. Build residual graph: residual(u,v) = c(u,v) - flow(u,v)
                         residual(v,u) = flow(u,v)  // backward edge
3. While ∃ augmenting path P from s to t in residual graph:
   (Use BFS for Edmonds-Karp — guarantees O(VE²))
   a. bottleneck = min residual capacity along P
   b. For each edge (u,v) on path P:
      - residual(u,v) -= bottleneck  (use capacity)
      - residual(v,u) += bottleneck  (allow undo)
   c. max_flow += bottleneck
4. Return max_flow

To find MIN CUT after algorithm:
  - Run BFS from s in final residual graph
  - S = reachable vertices, T = unreachable vertices
  - Min cut = edges from S to T in ORIGINAL graph
  - Min cut capacity = max flow (Max-Flow Min-Cut Theorem)

Worked Example

Network: S→A:10, S→B:8, A→B:2, A→T:6, B→T:10.

Iteration 1: BFS finds path S → A → T
  Bottleneck = min(10, 6) = 6
  Update: residual(S,A)=4, residual(A,T)=0, residual(A,S)=6, residual(T,A)=6
  max_flow = 6

Iteration 2: BFS finds path S → B → T
  Bottleneck = min(8, 10) = 8
  Update: residual(S,B)=0, residual(B,T)=2, residual(B,S)=8, residual(T,B)=8
  max_flow = 6 + 8 = 14

Iteration 3: BFS finds path S → A → B → T
  Bottleneck = min(4, 2, 2) = 2
  Update: residual(S,A)=2, residual(A,B)=0, residual(B,T)=0
  max_flow = 14 + 2 = 16

No more augmenting paths. MAX FLOW = 16.

Min cut: S reachable = {S,A}. Cut edges: S→B(8), A→B(2), A→T(6).
Hmm wait — let me recheck. Actually with these capacities: S→A cap 10, S→B cap 8...
After all flow: flow(S,A)=8, flow(S,B)=8, flow(A,B)=2, flow(A,T)=6, flow(B,T)=10.
Total out of S = 8+8 = 16. Total into T = 6+10 = 16. ✓
⚠️ You MUST update both forward AND backward edges. Backward edges allow the algorithm to "undo" bad choices. Forgetting backward edges = wrong answer.
Bellman-Ford — Shortest Path (Negative Weights OK)
INPUT: Weighted directed graph G, source s
OUTPUT: Shortest distances, or "negative cycle detected"

1. Initialize: dist[s] = 0, dist[v] = ∞ for all v ≠ s
2. Repeat (|V| - 1) times:
   For each edge (u, v, w) in graph:
       if dist[u] + w < dist[v]:
           dist[v] = dist[u] + w
           parent[v] = u
3. Check for negative cycle (ONE more pass):
   For each edge (u, v, w):
       if dist[u] + w < dist[v]:
           → NEGATIVE CYCLE EXISTS (shortest path undefined)

Worked Example: 4 vertices with a negative edge

Edges: A→B:4, A→C:3, B→C:-2, C→D:1. Source = A.

Edge order for each iteration: (A,B,4), (A,C,3), (B,C,-2), (C,D,1)

           | dist[A] | dist[B] | dist[C] | dist[D]
───────────┼─────────┼─────────┼─────────┼────────
Init       |    0    |    ∞    |    ∞    |    ∞
Iter 1:
  A→B(4)   |    0    |    4    |    ∞    |    ∞     ← 0+4<∞, update B
  A→C(3)   |    0    |    4    |    3    |    ∞     ← 0+3<∞, update C
  B→C(-2)  |    0    |    4    |    2    |    ∞     ← 4+(-2)=2<3, update C
  C→D(1)   |    0    |    4    |    2    |    3     ← 2+1=3<∞, update D
Iter 2:
  A→B(4)   |    0    |    4    |    2    |    3     ← no change
  A→C(3)   |    0    |    4    |    2    |    3     ← no change
  B→C(-2)  |    0    |    4    |    2    |    3     ← 4-2=2, not < 2
  C→D(1)   |    0    |    4    |    2    |    3     ← 2+1=3, not < 3
Iter 3:
  (no changes — converged)

Negative cycle check (Iter 4): No edge relaxes → NO negative cycle.
Shortest paths: A→A=0, A→B=4, A→B→C=2, A→B→C→D=3.
✓ V-1 iterations guarantees correctness (longest shortest path has at most V-1 edges). If it converges early, no need to continue — but on an exam, show all iterations.
Kahn's Algorithm — Topological Sort (DAG Only)
INPUT: Directed Acyclic Graph (DAG) G
OUTPUT: Topological ordering (linear order where u comes before v for every edge u→v)

1. Compute in-degree[v] for all vertices
2. queue = all vertices with in-degree 0
3. ordering = []
4. While queue is not empty:
   a. Dequeue vertex u
   b. Append u to ordering
   c. For each neighbor v of u:
      in-degree[v] -= 1
      if in-degree[v] == 0: enqueue v
5. If |ordering| < |V| → graph has a cycle (not a DAG!)
6. Return ordering

Worked Example: 6-vertex DAG

Edges: A→C, A→D, B→D, C→E, D→E, D→F, E→F.

Initial in-degrees: A=0, B=0, C=1, D=2, E=2, F=2
Queue starts: [A, B]

Step | Dequeue | Process edges      | In-degrees after    | Queue after  | Ordering
─────┼─────────┼───────────────────┼─────────────────────┼──────────────┼─────────
  1  |    A    | A→C (C:0), A→D    | C=0,D=1,E=2,F=2    | [B, C]       | [A]
  2  |    B    | B→D (D:0)         | C=0,D=0,E=2,F=2    | [C, D]       | [A,B]
  3  |    C    | C→E               | D=0,E=1,F=2        | [D]          | [A,B,C]
  4  |    D    | D→E (E:0), D→F   | E=0,F=1            | [E]          | [A,B,C,D]
  5  |    E    | E→F (F:0)        | F=0                 | [F]          | [A,B,C,D,E]
  6  |    F    | (none)            |                     | []           | [A,B,C,D,E,F]

Result: A, B, C, D, E, F  (one valid topological ordering — others exist)
⚠️ Only works on DAGs. If output has fewer than V vertices → cycle exists. Multiple valid orderings may exist (depends on queue tie-breaking).
Graham Scan — Convex Hull, O(n log n)
INPUT: Set of n points in 2D
OUTPUT: Vertices of convex hull in counterclockwise order

1. Find the point with lowest y-coordinate (leftmost if tie) → call it p₀
2. Sort remaining points by polar angle with respect to p₀
   (Use orientation test to compare angles. If same angle, keep closer point.)
3. Push p₀, p₁, p₂ onto stack
4. For each remaining point pᵢ (i = 3 to n-1):
   While orientation(second-to-top, top, pᵢ) is CLOCKWISE (or collinear):
       pop from stack
   Push pᵢ
5. Stack contains the convex hull vertices in CCW order

Orientation test for points p1, p2, p3:
  val = (p2.x - p1.x)(p3.y - p1.y) - (p2.y - p1.y)(p3.x - p1.x)
  val > 0 → counterclockwise (LEFT turn) → KEEP
  val < 0 → clockwise (RIGHT turn) → POP
  val = 0 → collinear → POP (keep farthest point only)

Worked Example: 6 points

Points: P0(0,0), P1(4,0), P2(3,3), P3(1,2), P4(2,4), P5(5,2).

Step 1: Lowest y-point = P0(0,0) ✓

Step 2: Sort by polar angle from P0:
  P1(4,0) → angle ≈ 0°
  P5(5,2) → angle ≈ 21.8°
  P2(3,3) → angle ≈ 45°
  P3(1,2) → angle ≈ 63.4°
  P4(2,4) → angle ≈ 63.4° (same angle as P3, but farther → P3 first)
  Sorted: P1, P5, P2, P3, P4

Step 3: Push P0, P1, P5
  Stack: [P0, P1, P5]

Step 4: Process P2(3,3):
  orientation(P1, P5, P2): (5-4)(3-0)-(2-0)(3-4) = 3-(-2) = 5 > 0 → CCW → KEEP
  Push P2. Stack: [P0, P1, P5, P2]

  Process P3(1,2):
  orientation(P5, P2, P3): (3-5)(2-2)-(3-2)(1-5) = 0-(-4) = 4 > 0 → CCW → KEEP
  Push P3. Stack: [P0, P1, P5, P2, P3]

  Process P4(2,4):
  orientation(P2, P3, P4): (1-3)(4-3)-(2-3)(2-3) = -2-(-1) = -1 < 0 → CW → POP P3
  orientation(P5, P2, P4): (3-5)(4-2)-(3-2)(2-5) = -4-(-3) = -1 < 0 → CW → POP P2
  orientation(P1, P5, P4): (5-4)(4-0)-(2-0)(2-4) = 4-(-4) = 8 > 0 → CCW → KEEP
  Push P4. Stack: [P0, P1, P5, P4]

Convex Hull: P0(0,0) → P1(4,0) → P5(5,2) → P4(2,4) → back to P0
BFS & DFS — Graph Traversal
BFS (Breadth-First Search):
  1. Start from source s. Mark s as visited. Enqueue s.
  2. While queue not empty:
     a. Dequeue vertex u
     b. For each unvisited neighbor v of u:
        Mark v visited, enqueue v, set parent[v] = u
  → Visits level by level. Gives shortest path in UNWEIGHTED graph.

DFS (Depth-First Search):
  1. Start from source s. Mark s as visited.
  2. For each unvisited neighbor v of s:
     Recursively DFS(v)
  (Or use explicit stack instead of recursion)
  → Goes as deep as possible before backtracking.

Both are O(V + E) time, O(V) space.

Quick Example: Graph A-B, A-C, B-D, C-D, D-E

BFS from A: Visit A → Queue [B,C] → Visit B → Queue [C,D] → Visit C → Queue [D] → Visit D → Queue [E] → Visit E
  Order: A, B, C, D, E

DFS from A (alphabetical neighbor order): Visit A → recurse B → recurse D → recurse C (already visited? skip) → recurse E
  Order: A, B, D, C, E  (depends on neighbor ordering)
Closest Pair of Points — Divide & Conquer, O(n log n)
INPUT: Set of n points in 2D
OUTPUT: The two closest points and their distance

1. Sort all points by x-coordinate
2. RECURSIVE FUNCTION closest(points):
   a. Base case: if ≤ 3 points, check all pairs (brute force)
   b. Divide: split into left half and right half at midpoint
   c. Conquer: δ_L = closest(left), δ_R = closest(right)
   d. δ = min(δ_L, δ_R)
   e. STRIP CHECK (the key insight!):
      - Find all points within distance δ of the midline
      - Sort these strip points by y-coordinate
      - For each point, compare with the NEXT 7 points in y-sorted order
      - Update δ if a closer pair is found
   f. Return δ

WHY 7 POINTS? In a δ×2δ rectangle, at most 8 points can fit with
pairwise distance ≥ δ. So checking 7 neighbors is sufficient.
✓ The strip check is what makes this O(n log n) instead of O(n²). Without it, you'd miss pairs that cross the dividing line.
Jarvis March (Gift Wrapping) — Convex Hull, O(nh)
INPUT: Set of n points
OUTPUT: Convex hull vertices in order

1. Start from the LEFTMOST point (guaranteed on hull)
2. current = leftmost
3. Repeat:
   a. next = any other point
   b. For each point p:
      if orientation(current, next, p) is CLOCKWISE:
          next = p   (p is "more counterclockwise" than next)
   c. Add next to hull
   d. current = next
   Until current == leftmost (back to start)

Comparison with Graham Scan:
  Graham Scan: O(n log n) always. Better when many hull points.
  Jarvis March: O(nh) where h = hull size. Better when h is very small (h ≪ n).
B3: NP-Completeness Deep Reference
P (Polynomial Time)
Problems where a SOLUTION can be FOUND in polynomial time. Examples: sorting O(n log n), shortest path O(VE), MST O(E log E). These are "easy" problems.
NP (Nondeterministic Polynomial Time)
Problems where a given SOLUTION can be VERIFIED in polynomial time. NOT "not polynomial"! Example: given a proposed Hamiltonian cycle, you can verify it visits all vertices in O(V) time. Note: P ⊆ NP (every P problem is also NP).
NP-Hard
At least as hard as ANY problem in NP. Every NP problem can be reduced to it in poly time. NP-Hard problems might NOT be in NP themselves (e.g., Halting Problem is NP-Hard but not in NP).
NP-Complete
Both NP AND NP-Hard. The hardest problems INSIDE NP. If you solve ANY NP-Complete problem in poly time → P = NP (million-dollar Millennium Prize). All NP-Complete problems are polynomially equivalent.
CRITICAL: How to Prove a Problem X is NP-Complete
Step 1 — Show X ∈ NP: Give a polynomial-time VERIFIER. "Given a candidate solution (certificate), I can check if it's valid in poly time."
Step 2 — Reduce from known NPC: Take a KNOWN NP-Complete problem Y and show Y ≤_p X (Y reduces to X in poly time). This means: "If I could solve X efficiently, I could solve Y efficiently."
DIRECTION MATTERS: You reduce FROM known hard TO new problem. NOT the other way around. Reducing new→known proves nothing.

Full Worked Proof: Independent Set is NP-Complete

Claim: Independent Set (IS) is NP-Complete.
Definition: Given graph G and integer k, does G contain k vertices with NO edges between any pair?

Step 1: IS ∈ NP
  Certificate: A set S of k vertices.
  Verifier: Check |S| = k (O(1)). For every pair (u,v) in S, check no edge exists (O(k²) ≤ O(V²)).
  This is polynomial. ✓ IS ∈ NP.

Step 2: Reduce Clique ≤_p IS
  Known: Clique is NP-Complete.

  Reduction: Given instance (G, k) of Clique, construct instance (Ḡ, k) of IS where:
    Ḡ = complement of G (edge exists in Ḡ iff it does NOT exist in G)
    k stays the same

  Construction time: O(V²) to build complement → polynomial ✓

  Correctness:
    (→) If G has a clique of size k → those k vertices are all connected in G
        → NO edges between them in Ḡ → they form an IS of size k in Ḡ ✓
    (←) If Ḡ has an IS of size k → those k vertices have NO edges in Ḡ
        → ALL edges exist between them in G → they form a clique of size k in G ✓

  Therefore: Clique has solution ↔ IS has solution. Reduction is polynomial.

Conclusion: IS ∈ NP and Clique ≤_p IS → IS is NP-Complete. ∎
The Reduction Chain
SAT (Boolean Satisfiability) — the "original" NP-Complete problem (Cook-Levin Theorem) ↓ reduces to 3-SAT (each clause has exactly 3 literals) ↓ reduces to CLIQUE (find complete subgraph of size k) ↓ reduces to (via complement graph) INDEPENDENT SET (find k vertices with no edges between them) ↓ reduces to (IS size k ↔ VC size n-k) VERTEX COVER (find k vertices that touch every edge) Separate chain: HAMILTONIAN CYCLE (visit every vertex exactly once, return to start) ↓ reduces to (add edge weights) TSP (Traveling Salesman: find shortest Hamiltonian cycle)
Key NP-Complete Problems — Definitions
SAT: Given a Boolean formula, is there an assignment of T/F to variables that makes it TRUE?
3-SAT: SAT where each clause has exactly 3 literals. Still NP-Complete.
Clique: Given graph G and integer k, does G contain a complete subgraph of k vertices (all pairs connected)?
Independent Set: Given G and k, are there k vertices with NO edges between any pair?
Vertex Cover: Given G and k, are there k vertices such that every edge has at least one endpoint in the set?
Hamiltonian Cycle: Does G contain a cycle that visits every vertex exactly once?
TSP: Given weighted complete graph and budget B, is there a Hamiltonian cycle of total weight ≤ B?
Key Relationships (Exam Favorites)
Clique ↔ Independent Set: Clique of size k in G = IS of size k in complement graph Ḡ. (Complement: flip all edges.)
Independent Set ↔ Vertex Cover: IS of size k in G ↔ VC of size (n−k) in G. (Remove IS vertices → remaining are VC.)
Implication: All three are polynomially equivalent. Solve one in poly time → solve all in poly time.
Ham. Cycle → TSP: Set all edge weights to 1. Ham. cycle exists ↔ TSP tour of cost n exists.
Approximation Algorithms
2-Approx Vertex Cover: While edges remain: pick any edge (u,v), add BOTH u and v to cover, remove all edges incident to u and v. Result is at most 2× optimal.
2-Approx Metric TSP: (Requires triangle inequality.) Find MST, do DFS preorder traversal, shortcut repeated vertices. Cost ≤ 2 × optimal TSP.
1.5-Approx TSP (Christofides): MST + minimum matching on odd-degree vertices + Eulerian circuit + shortcutting. (Know it exists, probably won't need details.)
Decision vs Optimization
Decision problem: Answer is YES or NO. "Does a Hamiltonian cycle exist?" "Is there a vertex cover of size ≤ k?"
Optimization problem: Find the BEST solution. "Find the shortest tour." "Find the smallest vertex cover."
Key point: NP-Completeness is defined for DECISION problems. If the decision version is hard, the optimization version is at least as hard.

B5: "When to Use What" Decision Guide
Shortest path, NO negative weights
→ Dijkstra's: O((V+E)log V) with heap, O(V²) with array.
Shortest path, negative weights
→ Bellman-Ford: O(VE). Detects negative cycles too.
Shortest path in a DAG
→ Topological sort + relaxation: O(V+E). Fastest option.
All-pairs shortest path
→ Floyd-Warshall: O(V³). Or run Dijkstra/BF from each vertex.
MST, sparse graph (E ≪ V²)
→ Kruskal's: O(E log E). Sort edges + Union-Find.
MST, dense graph (E ≈ V²)
→ Prim's: O(V²) with array. Grows from a vertex.
Maximum flow in network
→ Edmonds-Karp (BFS-based Ford-Fulkerson): O(VE²). Always terminates.
Topological ordering
→ Kahn's: O(V+E). Queue-based, clean to trace. Also detects cycles.
Convex hull, general case
→ Graham Scan: O(n log n). Standard choice.
Convex hull, few hull points
→ Jarvis March: O(nh). Better when h ≪ n.
Closest pair of points
→ Divide & Conquer: O(n log n). Don't forget the strip check.
Point inside polygon?
→ Ray casting: O(n). Cast ray, count edge intersections, odd = inside.
Prove problem is NP-Complete
→ (1) Show ∈ NP (poly verifier). (2) Reduce known NPC → your problem. Direction: FROM known TO new.
Detect cycle in directed graph
→ DFS (back edge = cycle) or Kahn's (output < V vertices = cycle).
Connected components
→ BFS or DFS from each unvisited vertex. Count components.
B6: 20 Common Exam Traps & Mistakes

Read this TWICE. These are the mistakes that drop you from 80% to 60%.

TRAP 1: Using Dijkstra with negative edge weights.
Dijkstra's greedy assumption fails — it may "lock in" a longer path before discovering a shorter one via a negative edge. Use Bellman-Ford instead.
TRAP 2: Thinking NP means "not polynomial."
NP = Nondeterministic Polynomial = verifiable in poly time. P ⊆ NP. Many NP problems ARE polynomial (all P problems are NP).
TRAP 3: Confusing NP-Hard and NP-Complete.
NP-Complete = NP-Hard AND in NP. NP-Hard can be outside NP entirely (e.g., Halting Problem). NP-Complete is the intersection.
TRAP 4: Reducing in the WRONG direction for NP-Complete proofs.
To prove X is NP-Complete: reduce FROM known NPC TO X. "Known ≤_p X." If you reduce X → Known, you only prove X is no harder than Known (useless).
TRAP 5: Forgetting backward edges in Ford-Fulkerson residual graph.
Backward edges allow "undoing" flow. Without them, the algorithm may get stuck at a suboptimal flow and miss the true max flow.
TRAP 6: Assuming greedy always gives optimal.
Greedy only works with greedy-choice property + optimal substructure. 0/1 knapsack, graph coloring, and many problems need DP or other approaches.
TRAP 7: Kruskal's: skipping edges that connect "visited" vertices instead of checking for cycles.
Kruskal's skips edges that create CYCLES (same Union-Find component), not edges to "visited" vertices. This isn't Prim's.
TRAP 8: Bellman-Ford: running V iterations instead of V-1.
V-1 iterations for finding shortest paths. The Vth iteration is ONLY for detecting negative cycles (not updating distances).
TRAP 9: Saying negative cycle means "longer path."
A negative cycle means shortest path is UNDEFINED (−∞). You can loop through the cycle forever, decreasing the cost infinitely.
TRAP 10: Topological sort on a graph with cycles.
Topological sort ONLY works on DAGs (Directed Acyclic Graphs). If a cycle exists, no valid topological ordering exists.
TRAP 11: Graham Scan: sorting by x-coordinate instead of polar angle.
Graham Scan sorts by polar angle from the anchor point (lowest-y). Sorting by x gives you something, but not the convex hull.
TRAP 12: Forgetting the strip check in closest pair.
The closest pair might cross the dividing line. The strip of width 2δ is where you find it. Skip this → potentially wrong answer.
TRAP 13: Orientation test sign convention mix-up.
Positive = CCW (left turn). Negative = CW (right turn). Zero = collinear. Getting this backwards flips your entire convex hull.
TRAP 14: Thinking all NP problems are hard.
P ⊆ NP. Sorting is in NP (you can verify a sorted array in O(n)). NP contains easy AND hard problems. NP-Complete problems are the hard ones.
TRAP 15: Adding more than V-1 edges in MST.
Any spanning tree of V vertices has exactly V-1 edges. Adding more creates a cycle. Kruskal's should stop at V-1 edges.
TRAP 16: Confusing Prim's and Dijkstra's.
Both use greedy vertex selection, but: Prim's stores EDGE WEIGHT to MST set (key[v] = min edge weight). Dijkstra stores TOTAL DISTANCE from source (dist[v] = dist[u] + w). Different purposes, similar structure.
TRAP 17: Saying Kruskal's and Prim's give different MSTs.
Both give a MINIMUM spanning tree. If edge weights are unique, both give the SAME MST (just built in different order). With ties, different MSTs are possible but same total weight.
TRAP 18: Ford-Fulkerson: confusing capacity with flow.
Residual capacity = original capacity − current flow (forward) or current flow (backward). The residual graph changes every iteration.
TRAP 19: Forgetting that Edmonds-Karp is just Ford-Fulkerson with BFS.
Plain Ford-Fulkerson (DFS) may not terminate with irrational capacities. Edmonds-Karp (BFS) guarantees termination and O(VE²). Always use BFS on exams unless told otherwise.
TRAP 20: Not showing work on algorithm tracing questions.
Even if your final answer is right, professors grade the STEPS. Show the full table, every iteration. Partial credit comes from showing correct intermediate steps.

Problem 5: Prove Vertex Cover is NP-Complete ▶

Problem: Given graph G = (V,E) and integer k, does G have a vertex cover of size ≤ k? (A vertex cover is a set S ⊆ V such that every edge has at least one endpoint in S.) Prove this is NP-Complete.

Claim: Vertex Cover (VC) is NP-Complete.

Step 1: Show VC ∈ NP
  Certificate: A set S of vertices with |S| ≤ k.
  Verifier:
    1. Check |S| ≤ k → O(1)
    2. For every edge (u,v) ∈ E, check that u ∈ S OR v ∈ S → O(E)
    Total: O(V + E) = polynomial ✓
  Therefore VC ∈ NP.

Step 2: Reduce Independent Set (IS) ≤_p VC
  Known: Independent Set is NP-Complete.

  Reduction: Given IS instance (G, j), create VC instance (G, k) where:
    - Use the SAME graph G
    - Set k = |V| - j  (that's it!)

  Construction time: O(1) → polynomial ✓

  Correctness proof:

  (→) Suppose G has an IS of size j (call it I).
      Let S = V \ I (all vertices NOT in I). |S| = |V| - j = k.
      Claim: S is a vertex cover.
      Proof: Take any edge (u,v). Since I is independent, u and v
      CANNOT both be in I. So at least one of them is in S = V \ I.
      Therefore S covers every edge. S is a VC of size k. ✓

  (←) Suppose G has a VC of size k (call it S).
      Let I = V \ S. |I| = |V| - k = |V| - (|V| - j) = j.
      Claim: I is an independent set.
      Proof: Suppose for contradiction that I contains adjacent vertices
      u and v. Then edge (u,v) has neither endpoint in S (since both
      are in I = V \ S). But S is a vertex cover — contradiction!
      Therefore I has no adjacent vertices. I is an IS of size j. ✓

  IS has solution ↔ VC has solution. Reduction is polynomial.

Conclusion: VC ∈ NP and IS ≤_p VC → Vertex Cover is NP-Complete. ∎

Key exam note: The reduction from IS to VC is one of the simplest.
Same graph, k = n - j. The insight: removing an IS leaves a VC, and vice versa.
