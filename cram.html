HOUR 2 (45 min)
Big-O + Graph Basics — Easy Points You Can't Miss
WHY SECOND
Definition and recall questions. You either know them or you don't. Pure memorization = guaranteed points. Exam often has 1-2 questions on Big-O hierarchy and graph representations.
MEMORIZE THIS
  • Big-O Hierarchy (smallest to largest): 1 < log n < √n < n < n log n < n² < n³ < 2ⁿ < n!
  • Formal Definition: f(n) = O(g(n)) iff ∃ c > 0, n₀ > 0 such that f(n) ≤ c·g(n) for ALL n ≥ n₀
  • Simplification: Drop constants, keep dominant term (3n² + 5n + 10 → O(n²))
GRAPH BASICS (NON-NEGOTIABLE)
  • Adjacency Matrix: O(V²) space, O(1) edge lookup, good for dense graphs
  • Adjacency List: O(V + E) space, O(degree) edge lookup, good for sparse graphs
  • BFS: Uses queue, O(V+E), unweighted shortest path
  • DFS: Uses stack/recursion, O(V+E), finds connected components
  • Graph Types: Directed, undirected, weighted, DAG, bipartite, complete graph K_n

HOUR 3 (45 min)
NP-Completeness — The Conceptual Framework
WHY HOUR 3
THIS WILL BE ON THE EXAM. Students lose points by confusing P, NP, NP-Hard, NP-Complete. The prof loves testing whether you understand the framework. This is conceptual but learnable in 45 minutes.
THE 4 CRITICAL DEFINITIONS
  • P: Problems solvable in polynomial time (yes/no answer computable in poly time)
  • NP: Problems VERIFIABLE in polynomial time (if yes, you can prove it in poly time). NP does NOT mean "not polynomial"!
  • NP-Hard: At least as hard as any NP problem. Might NOT be in NP. Informal: reducible from every NP problem.
  • NP-Complete: In NP AND NP-Hard. The hardest problems in NP. If you solve one in poly time, P=NP.
HOW TO PROVE NP-COMPLETE (2-STEP)
  • Step 1: Show the problem ∈ NP. Give a polynomial-time verifier. (Example: for Clique, given a set of vertices, verify in O(k²) that all k(k-1)/2 edges exist.)
  • Step 2: Reduce a KNOWN NP-Complete problem to yours in polynomial time. (Example: reduce SAT → 3-SAT → Clique)
THE REDUCTION CHAIN (MEMORIZE)
  • SAT → 3-SAT → Clique → Vertex Cover → Independent Set
  • Hamiltonian Cycle → TSP (Traveling Salesman Problem)
PROBLEM RELATIONSHIPS (KEY FOR EXAM)
  • Clique vs Independent Set: IS in complement graph ↔ Clique in original graph
  • Independent Set vs Vertex Cover: VC of size k ↔ IS of size n-k in same graph
  • Implication: If you solve one, you solve all three (via polynomial reduction)
ACTION ITEMS
  • ☐ Write P, NP, NP-Hard, NP-Complete definitions from memory
  • ☐ Explain why NP ≠ "not polynomial"
  • ☐ Explain the 2-step NP-Complete proof template
  • ☐ Draw or describe the reduction chain
  • ☐ Explain Clique ↔ IS ↔ VC relationships
HOUR 4 (45 min)
Topological Sort + Design Paradigms + Bellman-Ford
WHY HOUR 4
Mid-difficulty topics. Topological sort is straightforward to trace (you'll likely get the points). Bellman-Ford fills in the shortest-path picture. Design paradigms show you understand algorithm construction.
KAHN'S TOPOLOGICAL SORT (MEMORIZE)
  • 1. Compute in-degree of all vertices
  • 2. Add all in-degree 0 vertices to a queue
  • 3. While queue not empty: remove vertex, add to ordering, decrease in-degree of neighbors, add new 0-degree vertices
  • 4. If ordering doesn't have all vertices → cycle exists (not a DAG)
  • Complexity: O(V+E)
BELLMAN-FORD (HANDLES NEGATIVE WEIGHTS)
  • 1. Initialize all distances to ∞, source to 0
  • 2. Repeat V-1 times: for EACH edge (u,v,w), if dist[u] + w < dist[v], update dist[v]
  • 3. On Vth iteration, if any distance decreases → negative cycle detected
  • When to use: Negative edge weights OR you need cycle detection
  • Complexity: O(VE)
DESIGN PARADIGMS (CONCEPTUAL)
  • Greedy: Make locally optimal choices → globally optimal. Requires greedy-choice property + optimal substructure.
  • Divide & Conquer: Split problem, solve subproblems, combine. (Examples: merge sort, closest pair, quick sort)
  • Dynamic Programming: Store subproblem results to avoid recomputation. (Examples: LCS, knapsack, shortest path)
  • Brute Force: Try all possibilities. Exponential time, but guarantees optimal solution.
ACTION ITEMS
  • ☐ Trace Kahn's algorithm on a DAG (5-6 vertices)
  • ☐ Trace Bellman-Ford on a graph with negative weights
  • ☐ Explain why Dijkstra fails on negative weights (example: edge weight -1)
  • ☐ Describe one problem solved by greedy, divide & conquer, and DP
HOUR 5 (45 min)
Geometric Algorithms — The Detail-Heavy Topic
WHY HOUR 5
These are detail-heavy but on the exam. The prof covered them extensively. You need to know the algorithm steps, not just the idea. Most students skip this — don't. Exam often has 1 problem on Graham Scan or orientation test.
ORIENTATION TEST (YOU NEED THIS)
  • Formula: (p2.x - p1.x)(p3.y - p1.y) - (p2.y - p1.y)(p3.x - p1.x)
  • Interpretation: Positive = counterclockwise (CCW), Negative = clockwise (CW), Zero = collinear
  • Use case: Determines if three points turn left or right. Foundation for convex hull algorithms.
GRAHAM SCAN (CONVEX HULL)
  • 1. Find the lowest-y point (leftmost if tie). Call it p0.
  • 2. Sort remaining points by polar angle with respect to p0. (Highest angle last.)
  • 3. Push p0, p1, p2 onto stack
  • 4. For each remaining point p: while stack has ≥2 points and top-2 + p make clockwise turn, pop. Push p.
  • 5. Stack contains hull vertices in CCW order.
  • Complexity: O(n log n)
JARVIS MARCH (GIFT WRAPPING)
  • 1. Start with leftmost point
  • 2. Repeatedly pick the point that is most counterclockwise from the current direction
  • 3. Stop when you return to start
  • Complexity: O(nh) where h = number of hull points. Good when hull is small.
CLOSEST PAIR (DIVIDE & CONQUER)
  • 1. Sort points by x-coordinate
  • 2. Divide into left/right halves at midpoint
  • 3. Recursively find closest pair in each half: δ_L, δ_R
  • 4. Let δ = min(δ_L, δ_R)
  • 5. Check the strip: all points within distance δ of the dividing line. For each point, check at most 7 points above it (sorted by y).
  • 6. Return closest pair overall
  • Complexity: O(n log n)
POINT-IN-POLYGON (RAY CASTING)
  • Cast a ray from point to infinity (usually rightward along x-axis)
  • Count intersections with polygon edges
  • Odd count = inside, even count = outside

B2: Algorithm Step-by-Step Cheatsheets

These are the EXACT steps to trace on the exam. Memorize the format.

Dijkstra's Algorithm (Shortest Path, No Negative Weights)
INPUT: Graph G, source s OUTPUT: Shortest distances dist[] and parent pointers 1. Initialize: dist[s] = 0, dist[v] = ∞ for all v ≠ s, parent[v] = null 2. Create set "unvisited" = all vertices 3. While unvisited is not empty: a. Pick u from unvisited with minimum dist[u] b. Remove u from unvisited c. For each neighbor v of u: - If dist[u] + weight(u,v) < dist[v]: - dist[v] = dist[u] + weight(u,v) - parent[v] = u 4. Return dist[] and parent[] TABLE FORMAT (for your answer): Step | Visited | d[A] | d[B] | d[C] | d[D] | Parent[A] | Parent[B] | ... 0 | {} | 0 | ∞ | ∞ | ∞ | - | - | ... 1 | {A} | 0 | 4 | 2 | ∞ | - | A | A | ... ... continue until all visited
⚠️ FAILS on negative edge weights. Use Bellman-Ford instead.
Prim's Algorithm (Minimum Spanning Tree)
INPUT: Graph G OUTPUT: Minimum spanning tree edges 1. Start with any vertex (say s), add to MST set 2. Initialize key[v] = ∞ for all v, key[s] = 0 3. While MST set doesn't contain all vertices: a. Pick vertex u NOT in MST with minimum key[u] b. Add u to MST set c. For each edge (u,v) where v is not in MST: - If weight(u,v) < key[v]: - key[v] = weight(u,v) - parent[v] = u (track edge for output) 4. Return MST edges using parent pointers TABLE FORMAT: Step | MST Set | key[A] | key[B] | key[C] | Edge Added 1 | {A} | 0 | 5 | 7 | - 2 | {A,B} | 0 | 5 | 3 | (A,B,5) ... continue until all vertices in MST
⚠️ Good for dense graphs. Use Kruskal's for sparse.
Kruskal's Algorithm (Minimum Spanning Tree)
INPUT: Graph G with edges OUTPUT: Minimum spanning tree edges 1. Sort all edges by weight (ascending) 2. Initialize Union-Find structure (each vertex in its own set) 3. For each edge (u,v,w) in sorted order: a. If find(u) ≠ find(v): // u and v in different components - Add edge (u,v) to MST - union(u,v) // merge components b. Else: skip edge (would create cycle) 4. Return MST edges TABLE FORMAT: Edge | Weight | find(u) | find(v) | Action | Reason (A,B) | 1 | 0 | 1 | Add | Different sets (B,C) | 2 | 0 | 2 | Add | Different sets (A,C) | 3 | 0 | 0 | Skip | Same set (cycle) ... continue for all edges
⚠️ Exactly |V|-1 edges in MST. Don't add more.
Ford-Fulkerson Algorithm (Maximum Flow)
INPUT: Flow network with source s, sink t, capacities c(u,v) OUTPUT: Maximum flow value and flow on each edge 1. Initialize flow[u,v] = 0 for all edges 2. Build residual graph: res[u,v] = c[u,v] - flow[u,v] 3. While there exists augmenting path P from s to t in residual graph: a. Find minimum capacity (bottleneck) along P: b = min(res along P) b. For each edge (u,v) in P: - flow[u,v] += b // increase forward flow - flow[v,u] -= b // increase backward flow (undo) - Update residual: res[u,v] -= b, res[v,u] += b c. Add b to total max flow 4. Return max flow and final flow array EXAMPLE (3-node network, s=A, t=C): Initial: A->B cap 10, A->C cap 5, B->C cap 8 Path 1: A->B->C, bottleneck=min(10,8)=8 flow[A,B]=8, flow[B,C]=8, maxflow=8 Path 2: A->C, bottleneck=5 flow[A,C]=5, maxflow=13 No more augmenting paths → maxflow=13
⚠️ Update BOTH forward and backward edges in residual graph. Backward edges allow "undoing".
Bellman-Ford Algorithm (Shortest Path, Negative Weights OK)
INPUT: Graph G, source s OUTPUT: Shortest distances, or "negative cycle detected" 1. Initialize: dist[s] = 0, dist[v] = ∞ for v ≠ s 2. Repeat |V|-1 times: - For EACH edge (u,v,w): - If dist[u] + w < dist[v]: - dist[v] = dist[u] + w 3. Check for negative cycle (|V|th iteration): - For EACH edge (u,v,w): - If dist[u] + w < dist[v]: - Return "Negative cycle detected" 4. Return dist[] WHY |V|-1? A shortest path has at most |V|-1 edges. After |V|-1 iterations, all shortest paths found. If iteration |V| still updates, there's a cycle.
⚠️ Slower than Dijkstra (O(VE) vs O(V log V)), but handles negatives + detects cycles.
Kahn's Algorithm (Topological Sort of DAG)
INPUT: Directed acyclic graph (DAG) OUTPUT: Topological ordering or "not a DAG" 1. Compute in-degree for each vertex 2. Add all in-degree 0 vertices to a queue 3. While queue is not empty: a. Remove vertex u from queue b. Add u to topological ordering c. For each neighbor v of u: - Decrement in-degree[v] - If in-degree[v] becomes 0, add v to queue 4. If topological ordering has all vertices: return ordering Else: return "Graph has a cycle" EXAMPLE: A->B, A->C, B->D, C->D In-degrees: A=0, B=1, C=1, D=2 Queue: [A] Pop A, add to order: [A], decrease in-degree[B] and in-degree[C] in-degrees: B=0, C=0, D=2 Add B,C to queue: [B,C] Pop B, add to order: [A,B], decrease in-degree[D] in-degrees: D=1 Queue: [C] Pop C, add to order: [A,B,C], decrease in-degree[D] in-degrees: D=0 Queue: [D] Pop D, add to order: [A,B,C,D] Result: [A,B,C,D] or [A,C,B,D] are valid topological orderings
⚠️ Only works on DAGs. If cycles exist, it will detect them (not all vertices processed).
Graham Scan (Convex Hull)
INPUT: Set of n points in 2D OUTPUT: Convex hull vertices in counterclockwise order 1. Find the point p0 with lowest y-coordinate (leftmost if tie) 2. Sort remaining points by polar angle with respect to p0 - Use cross product to compare angles: (p-p0) × (q-p0) 3. Initialize: stack = [p0, p1, p2] 4. For i = 3 to n-1: p = points[i] While stack has ≥2 points AND ccw(stack[-2], stack[-1], p) ≤ 0: (ccw = cross product orientation test; ≤0 means clockwise or collinear) stack.pop() stack.push(p) 5. Stack contains hull vertices in CCW order ORIENTATION TEST: (q.x-p.x)(r.y-p.y) - (q.y-p.y)(r.x-p.x) > 0: counter-clockwise, < 0: clockwise, = 0: collinear
⚠️ Sort by POLAR ANGLE, not x-coordinate. Polar angle means angle from p0.
Jarvis March (Gift Wrapping Convex Hull)
INPUT: Set of n points in 2D OUTPUT: Convex hull vertices in counterclockwise order 1. Find leftmost point, add to hull 2. current_point = leftmost point 3. While current_point is not the starting point: a. next_point = any other point (or first point initially) b. For each remaining point p: - If p is more counterclockwise from current_point than next_point: - next_point = p - Use orientation test: if cross product < 0, then p is more CCW c. Add next_point to hull d. current_point = next_point 4. Return hull COMPLEXITY: O(nh) where h = number of hull points - Good when hull is small (h << n) - Bad when hull is large (h ≈ n)
⚠️ Slower than Graham Scan (O(nh) vs O(n log n)), but simple and good for small hulls.
Closest Pair of Points (Divide & Conquer)
INPUT: Set of n points, sorted by x-coordinate OUTPUT: Distance between closest pair 1. Base case: if n ≤ 3, return closest pair by brute force O(1) 2. Divide: split points at midpoint x = mid_x - Left points = points[0..mid] - Right points = points[mid+1..n] 3. Conquer: - δL = closest pair distance in left half - δR = closest pair distance in right half - δ = min(δL, δR) 4. Check strip: find all points within distance δ of dividing line (x = mid_x) - For each point p in strip (sorted by y): - For j = 1 to 7 (or until y-distance > δ): - Compute distance to next 7 points above p - Update δ if closer pair found 5. Return δ WHY 7? In a δ×2δ rectangle, at most 8 points fit with min distance δ.
⚠️ The "7 points" check is the key optimization. Don't forget the strip.
B3: NP-Completeness Quick Reference
P (Polynomial Time)
Problems solvable in polynomial time. There exists an algorithm that computes the answer (yes/no) in O(poly(n)) time.
NP (Nondeterministic Polynomial Time)
Problems whose SOLUTIONS can be VERIFIED in polynomial time. NOT "not polynomial." If someone gives you a solution, you can check if it's correct in poly time.
NP-Hard
At least as hard as any NP problem. Every NP problem reduces to it in poly time. NP-Hard problems might NOT be in NP.
NP-Complete
Both NP AND NP-Hard. The hardest problems in NP. If you solve one in poly time, P=NP (and you win a million dollars).
CRITICAL: How to Prove NP-Complete
  • Step 1: Show ∈ NP — Provide a polynomial-time verifier. "Given a candidate solution, I can check if it's valid in poly time."
  • Step 2: Reduce from NP-Complete — Take a KNOWN NP-Complete problem and reduce it to yours in poly time. "If I could solve your problem in poly time, I could solve [known hard] in poly time."
  • Result: Your problem is NP-Complete.
THE REDUCTION CHAIN
SAT (Boolean Satisfiability) ↓ reduces to 3-SAT (Each clause has ≤3 literals) ↓ reduces to Clique (Find k vertices, all connected) ↓ reduces to Vertex Cover (Find k vertices touching all edges) ↓ reduces to Independent Set (Find k vertices, NO edges between) SEPARATE CHAIN: Hamiltonian Cycle (Visit every vertex once, return to start) ↓ reduces to TSP (Traveling Salesman: shortest Hamiltonian cycle)
KEY RELATIONSHIPS (Exam Loves These)
  • Clique ↔ Independent Set: Clique in graph G = Independent Set in complement graph Ḡ. (Complement: opposite edges.)
  • Independent Set ↔ Vertex Cover: IS of size k in G ↔ VC of size n-k in G. (Complement of VC = IS.)
  • Result: All three are equally hard (polynomial-time equivalent). Solve one, solve all.
B4: Key Formulas & Definitions to Memorize
Big-O Definition: f(n) = O(g(n)) iff ∃ c > 0, n₀ > 0 such that f(n) ≤ c·g(n) ∀ n ≥ n₀
Big-Ω Definition: f(n) = Ω(g(n)) iff ∃ c > 0, n₀ > 0 such that f(n) ≥ c·g(n) ∀ n ≥ n₀
Big-Θ Definition: f(n) = Θ(g(n)) iff f(n) = O(g(n)) AND f(n) = Ω(g(n))
Orientation Test (3D Cross Product): (p2.x - p1.x)(p3.y - p1.y) - (p2.y - p1.y)(p3.x - p1.x)
→ 0: CCW, < 0: CW, = 0: Collinear
Max-Flow Min-Cut Theorem: Maximum flow = Minimum cut capacity
Handshaking Lemma: Sum of all vertex degrees = 2|E|
Tree Properties: |E| = |V| - 1, connected, acyclic (any 2 ⇒ 3rd)
MST Cut Property: For any cut (S, V-S), minimum edge crossing it is in some MST
MST Cycle Property: For any cycle, maximum weight edge is NOT in any MST
Relaxation: If d[v] > d[u] + w(u,v), then d[v] = d[u] + w(u,v)
B5: "When to Use What" Decision Guide
⚡ Shortest path, NO negative weights
→ Dijkstra's: O((V+E)log V) with min-heap, O(V²) with array. Fastest option.
⚡ Shortest path, negative weights allowed
→ Bellman-Ford: O(VE). Slower but handles negatives + detects cycles.
⚡ Shortest path in a DAG
→ Topological sort + single-pass relaxation: O(V+E). Faster than Dijkstra/Bellman-Ford.
⚡ Minimum spanning tree, sparse graph (E << V²)
→ Kruskal's: O(E log E). Sort edges, Union-Find. Good for sparse.
⚡ Minimum spanning tree, dense graph (E ≈ V²)
→ Prim's: O(V²) with array. Same result, different approach (grow from vertex).
⚡ Maximum flow in a network
→ Ford-Fulkerson (DFS) or Edmonds-Karp (BFS): O(VE²). Edmonds-Karp guaranteed to terminate.
⚡ Topological ordering of a DAG
→ Kahn's: O(V+E), queue-based. Or DFS-based. Kahn's is cleaner to trace on exam.
⚡ Convex hull, general points
→ Graham Scan: O(n log n). Sort by polar angle. Fast and standard.
⚡ Convex hull, few hull points expected
→ Jarvis March: O(nh) where h = hull points. Good when h << n.
⚡ Closest pair of points
→ Divide & Conquer: O(n log n). Key: don't forget the strip optimization.
⚡ Prove a problem is NP-Complete
→ (1) Show ∈ NP (poly-time verifier). (2) Reduce known NP-Complete to it. Direction matters!
B6: Common Exam Traps & Mistakes (READ THIS!)
TRAP 1: Using Dijkstra with negative weights
Dijkstra FAILS on negative edges. It assumes once a vertex is visited, its distance won't improve. Counterexample: shortest path might go backward through a negative edge. Use Bellman-Ford instead.
TRAP 2: Greedy doesn't always work
Greedy only gives optimal solution if greedy-choice property + optimal substructure hold. For Kruskal's/Prim's/Dijkstra: proven to work. For arbitrary problems: PROVE IT or give counterexample.
TRAP 3: "NP" = "not polynomial"
WRONG. NP = nondeterministic polynomial = verifiable in poly time. You can check a solution quickly, but finding it might be hard. Example: Sudoku solution is verifiable in O(n²), finding it is hard.
TRAP 4: Confusing NP-Hard and NP-Complete
NP-Hard = at least as hard as any NP problem. Might NOT be in NP (e.g., undecidable problems). NP-Complete = NP AND NP-Hard. All NP-Complete problems equally hard, reducible to each other.
TRAP 5: Skipping edges in Kruskal's
You skip an edge if it would CREATE A CYCLE (both endpoints in same Union-Find set), NOT just if it connects a visited vertex. The difference: visited doesn't track components correctly after branching.
TRAP 6: Ford-Fulkerson: forgetting backward edges
When you send flow along an edge (u,v), you MUST update both: forward capacity decreases, backward capacity increases. Backward edges allow "undoing" flow. Without them, algorithm breaks.
TRAP 7: Graham Scan sorting wrong
Sort by POLAR ANGLE with respect to p0, not by x-coordinate. Polar angle means the angle from p0 to each point. Use atan2 or cross product to compare angles without computing them explicitly.
TRAP 8: Bellman-Ford iteration count
Relax ALL edges exactly |V|-1 times, THEN check |V|th iteration for negative cycles. Don't stop early, don't use |V| relaxations initially.
TRAP 9: Negative cycle = undefined shortest path
If negative cycle is on path from s to t, shortest path is undefined (can loop forever, making path arbitrarily negative). Report it, don't ignore it.
TRAP 10: Topological sort on cyclic graph
Kahn's only works on DAGs (directed acyclic graphs). If graph has cycle, algorithm won't process all vertices. Check: if sorted order has < n vertices, there's a cycle.
TRAP 11: Forgetting strip in Closest Pair
Divide & conquer finds closest in left, closest in right. But closest overall might be across the midline! The strip (width 2δ around dividing line) catches these. Don't skip it.
TRAP 12: NP-Complete reduction direction
To prove problem X is NP-Complete, reduce FROM known NP-Complete TO X. Wrong direction: you've proven X is at least as easy, not hard. Direction: NPC → X.
TRAP 13: Independent Set / Vertex Cover complement
IS of size k ↔ VC of size n-k in SAME graph. Not different graphs. The complement of an IS (all other vertices) is a VC.
TRAP 14: Orientation test sign
Cross product > 0 = counter-clockwise (left turn), < 0 = clockwise (right turn), = 0 = collinear. Get the sign right or your convex hull is backward.
TRAP 15: Greedy vs DP choice
Greedy = make best local choice immediately, never reconsider. DP = make locally optimal choice but store subproblem results. Greedy is faster but risky; DP is safer but slower. Know when each applies.
