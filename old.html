Big-O Notation Core

Session 2

Big-O notation describes how an algorithm's runtime (or space) grows relative to input size as the input gets arbitrarily large. We focus on the worst case.

Formal Definition

T(n) is O(F(n)) if there exist constants C > 0 and n₀ such that for all n > n₀:

T(n) ≤ C · F(n)

Simplification Rules

  • Drop constants: 5n → O(n)
  • Drop lower-order terms: n² + 3n + 7 → O(n²)
  • Worst case by default unless stated otherwise

Space Complexity

Measures total size of new variables allocated, relative to input. Same Big-O rules apply. Optimize for memory when relevant, but beware premature optimization that hurts readability.

Graph Basics & Traversals Core

Sessions 11 & 12

Key Definitions

  • Vertex (Node): A point in the graph
  • Edge: A connection between two vertices
  • Adjacency: Two vertices connected by an edge
  • Path: Sequence of edges between two vertices
  • Degree: Number of edges incident to a vertex — deg(v) ≤ n−1 in a simple graph
  • In-degree / Out-degree (directed): Edges coming in / going out
  • Distance d(U,V): Number of edges in the shortest path
  • Eccentricity e(V): Maximum distance from V to any other vertex

Directed vs Undirected

In an undirected graph, edge {a,b} = {b,a}. In a directed graph (digraph), edge (a,b) ≠ (b,a) — each edge has an arrow.

Simple Graph

No loops, no parallel edges. Max edges in a simple graph with n vertices: n(n−1)/2. Number of possible simple graphs with n vertices: 2^(n(n−1)/2).

Graph Representations

Traversal Algorithms

Depth-First Search (DFS) — Uses a Stack

  1. Visit adjacent unvisited vertex, mark visited, push to stack
  2. If no adjacent unvisited vertex, pop from stack
  3. Repeat until stack empty

Time: O(V + E)  |  Space: O(V)

Breadth-First Search (BFS) — Uses a Queue

  1. Visit adjacent unvisited vertex, mark visited, enqueue
  2. If no adjacent unvisited vertex, dequeue front vertex
  3. Repeat until queue empty

Time: O(V + E)  |  Space: O(V)

Critical Graph Elements

  • Spanning Tree: Subgraph connecting all vertices with minimum edges (V−1 edges, no cycles). Every connected undirected graph has at least one.
  • Cut Vertex: Removing it disconnects the graph
  • Cut Edge (Bridge): Removing it disconnects the graph. An edge is a bridge iff it's not part of any cycle. Max cut edges = n−1.
  • Cut Set: Minimum set of edges whose removal disconnects the graph
  • Complement G': Same vertices; edge {u,v} in G' iff edge not in G. G ∪ G' = Kₙ.

Minimum Spanning Trees Core

Session 15

A Minimum Spanning Tree (MST) of a weighted, connected, undirected graph is a spanning tree whose total edge weight is minimized. It has exactly V−1 edges.

Kruskal's Algorithm (Edge-based, Greedy)

Strategy: Sort edges by weight, greedily add smallest edge that doesn't create a cycle.

KRUSKAL(G):
  A = ∅
  for each v ∈ V: MAKE-SET(v)
  Sort edges by weight (ascending)
  for each edge (u,v) in sorted order:
    if FIND-SET(u) ≠ FIND-SET(v):
      A = A ∪ {(u,v)}
      UNION(u, v)
  return A

Time: O(E log E)  (dominated by sorting)  |  Uses Union-Find for cycle detection

Kruskal's Worked Example

Graph with 9 vertices, 14 edges. Edges sorted: 1, 2, 2, 4, 4, 6, 7, 7, 8, 8, 9, 10, 11, 14.

Selection: Pick edges with weights 1, 2, 2, 4, 4, 7, 7, 8 (skip any that create cycles). After adding V−1 = 8 edges, MST is complete.

Prim's Algorithm (Vertex-based, Greedy)

Strategy: Grow MST from a starting vertex; always add the cheapest edge connecting a tree vertex to a non-tree vertex.

PRIM(G, start):
  ReachSet = {start}
  UnReachSet = V − {start}
  MST = ∅
  while UnReachSet ≠ ∅:
    Find min-weight edge (x,y) where x ∈ ReachSet, y ∈ UnReachSet
    MST = MST ∪ {(x,y)}
    ReachSet = ReachSet ∪ {y}
    UnReachSet = UnReachSet − {y}
  return MST

Time: O((V + E) log V) with binary heap  |  O(E + V log V) with Fibonacci heap

Prim's — Distance Table Method

Maintain a table with columns: Vertex, Distance (to nearest tree vertex), Parent. Initialize all distances to ∞ except the start vertex (distance 0). At each step, pick the unvisited vertex with smallest distance, add it to tree, and update neighbors' distances.

Shortest Path Algorithms Core

Session 16

Problem Variations

  • Single Source Single Destination (SSSD)
  • Single Source Multiple Destination (SSMD)
  • Multiple Source Single / Multiple Destination

Dijkstra's Algorithm

Requirement: All edge weights must be non-negative.

DIJKSTRA(G, source):
  for each v ∈ V:
    dist[v] = ∞;  prev[v] = null
  dist[source] = 0
  Q = all vertices

  while Q ≠ ∅:
    u = vertex in Q with min dist[u]
    remove u from Q
    for each neighbor v of u still in Q:
      new_dist = dist[u] + weight(u,v)
      if new_dist < dist[v]:
        dist[v] = new_dist
        prev[v] = u
  return dist[], prev[]

Time: O((V + E) log V) with binary heap  |  Greedy: always picks closest unvisited vertex

Dijkstra Step-by-Step

Maintain a distance table. Start with source = 0, all others = ∞. Visit the unvisited node with smallest distance, update its neighbors via relaxation: if dist[u] + w(u,v) < dist[v], update dist[v]. Mark node visited. Repeat until all nodes visited or target reached.

Bellman-Ford Algorithm

Advantage: Handles negative edge weights. Can detect negative cycles.

BELLMAN-FORD(V, E, source):
  for each v ∈ V:
    dist[v] = ∞;  pred[v] = null
  dist[source] = 0

  // Relax all edges V-1 times
  for i = 1 to |V| - 1:
    for each edge (u,v,w) ∈ E:
      if dist[u] + w < dist[v]:
        dist[v] = dist[u] + w
        pred[v] = u

  // Detect negative cycles
  for each edge (u,v,w) ∈ E:
    if dist[u] + w < dist[v]:
      ERROR "Negative-weight cycle detected"

  return dist[], pred[]

Time: O(V · E)  |  Slower than Dijkstra but more versatile

Network Flow Core

Session 17

Problem Setup

Given directed graph G = (V, E) with edge capacities c(e) > 0, source s, and sink t. Goal: Maximize flow from s to t subject to:

  • Capacity constraint: 0 ≤ flow(e) ≤ capacity(e) for every edge
  • Conservation: For every non-source/sink node: total flow in = total flow out
  • Skew symmetry: f(u,v) = −f(v,u)

Ford-Fulkerson Method

FORD-FULKERSON(G, s, t):
  Initialize flow on all edges to 0
  while ∃ augmenting path P from s to t in residual graph:
    bottleneck = min capacity along P
    Augment flow along P by bottleneck
    Update residual graph:
      - Subtract bottleneck from forward edges
      - Add bottleneck to reverse edges
  return total flow

Key concepts:

  • Residual Graph: Shows remaining capacity on each edge; includes reverse edges to allow "undoing" flow
  • Augmenting Path: Any path from s to t in residual graph with positive capacity
  • Bottleneck: Minimum capacity along the augmenting path

Ford-Fulkerson Worked Example

Find augmenting paths one at a time. After each path, update the residual graph by subtracting the bottleneck from forward edges and adding it to reverse edges:

StepAugmenting PathBottleneckCumulative Flow
1S → C → D → B → T77
2S → C → D → T18
3S → A → B → T513
4S → A → C → D → T215

No more augmenting paths in residual graph. Max Flow = 15

Residual graph update at each step: For every edge (u,v) on the path with bottleneck f: reduce capacity(u,v) by f, increase capacity(v,u) by f. Reverse edges allow the algorithm to "undo" previous flow decisions.

Dinic's Algorithm (Faster)

Uses level graphs (BFS assigns levels = distance from source) and blocking flows (saturate at least one edge per path). Process:

  1. Build level graph using BFS from source
  2. Find blocking flow (DFS through level graph)
  3. Update residual graph; remove saturated edges and dead-end nodes
  4. Repeat until no path from s to t exists in level graph
DINIC(G, s, t):
  F = 0
  while BFS builds a level graph with path s→t:
    while ∃ blocking flow f in level graph:
      F = F + f
      Update residual graph
  return F

Time: O(V² · E) — generally faster than basic Ford-Fulkerson in practice.

Max-Flow Min-Cut Theorem

The maximum flow from s to t equals the minimum capacity of any s-t cut (partition separating s and t). This is a fundamental duality result.

Topological Sort & DAGs Core

Session 21

A topological ordering of a DAG (Directed Acyclic Graph) is a linear ordering of vertices such that for every directed edge (u, v), vertex u appears before v. Multiple valid orderings may exist. Only possible on DAGs — if a cycle exists, no valid ordering exists.

Kahn's Algorithm (BFS-based)

KAHN(G):
  Compute in-degree for each vertex
  Q = queue of all vertices with in-degree 0
  result = []
  while Q ≠ ∅:
    v = dequeue from Q
    result.append(v)
    for each neighbor u of v:
      in-degree[u] -= 1
      if in-degree[u] == 0:
        enqueue u
  if |result| ≠ |V|:
    ERROR "Graph has a cycle!"
  return result

Time: O(V + E)  |  Also useful for cycle detection

Critical Path Method (CPM)

Used for project scheduling. Models tasks and dependencies as a DAG.

  • Critical time of a task = max(critical times of prerequisites) + task's own time
  • Critical path = longest path through the DAG = minimum project completion time
  • Tasks not on the critical path have slack (can be delayed without affecting total time)

Example

Tasks A(0.3s), B(0.5s), C(0.4s), D(0.7s), E(0.1s) with dependencies. Serial time = 2.0s. Critical path A→B→C→E = 1.3s (allows parallel execution of D).

Algorithm Design Paradigms Core

Session 18

Divide & Conquer

  • Divide: Break problem into smaller subproblems
  • Conquer: Recursively solve subproblems
  • Combine: Merge solutions into overall answer

Examples: Binary search, merge sort, quick sort, closest pair of points. Runtime depends on division cost + combination cost + number of subproblems.

Greedy Algorithms

Build a solution step-by-step by always making the locally optimal choice. At each step: consider extensions → discard infeasible ones → pick the one that optimizes the objective function.

Examples: Prim's, Kruskal's, Dijkstra's, Huffman coding, shortest-job-first scheduling.

Caution: Greedy doesn't always yield the globally optimal solution!

Project Selection Example (From Class)

10 projects, 26-week deadline, each with completion time and expected revenue:

StrategyRevenueOptimality
Greedy-by-time$400K77%
Greedy-by-revenue$470K90%
Greedy-by-revenue-density$490K94%
Brute force (optimal)$520K100%

The revenue-density (revenue/week) heuristic came closest to optimal.

Process Scheduling — Shortest Job First is Optimal

To minimize total wait time for N processes on a single processor, schedule by shortest completion time first. Total wait = 4·t₁ + 3·t₂ + 2·t₃ + t₄ — minimized when t₁ ≤ t₂ ≤ t₃ ≤ t₄. This extends to multiple processors.

Brute Force

Enumerate all possible solutions, check each for validity. Simplest but slowest. Useful as a baseline to verify greedy/DP solutions are near-optimal.

Point-in-Shape Tests

Point Inside Triangle

Given triangle ABC and point P: compute Area(PAB) + Area(PBC) + Area(PAC). If this sum equals Area(ABC), then P is inside the triangle.

Point Inside Rectangle

Same approach: split rectangle ABCD into triangles with P. If A₁+A₂+A₃+A₄ = Area(ABCD), P is inside.

Point Inside Polygon (Ray Casting)

Draw a horizontal ray from P to the right (→ ∞). Count intersections with polygon edges:

  • Odd count → P is inside
  • Even count → P is outside
  • If P lies on an edge or vertex → considered inside

Circle Problems

Given circles with centers C₁(x₁,y₁), C₂(x₂,y₂) and radii R₁, R₂. Let d = distance(C₁, C₂):

ConditionResult
d = R₁ + R₂Touch externally
d > R₁ + R₂Don't intersect
d < R₁ + R₂Intersect

Collinearity & Maximum Points on a Line

For each point p, compute slope to all other points. Points with the same slope (relative to p) are collinear with p. Track maximum count. Time: O(n²).

Checking if Four Points Form a Square

  1. All four sides must have equal length d
  2. Both diagonals must have equal length √2·d
  3. Angle between any two adjacent sides must be 90°

Simple Closed Path

  1. Find bottom-most point (min y; break ties by min x) → call it P₀
  2. Sort remaining points by polar angle counterclockwise around P₀
  3. Traverse sorted array → yields non-self-intersecting closed path

Uses orientation test instead of computing actual angles.

Closest Pair of Points (Divide & Conquer)

Brute force: O(n²). D&C: O(n log n).

  1. Sort points by x-coordinate
  2. Split into left and right halves at midpoint
  3. Recursively find closest pair in each half: dₗ, dᵣ. Let d = min(dₗ, dᵣ)
  4. Build strip of points within distance d of the dividing line
  5. Sort strip by y-coordinate, check each point against next 7 points only
  6. Return min(d, closest pair in strip)

Key insight: Only 7 neighbors need checking per strip point (geometric proof).

Optimum Point on a Line (Ternary Search)

Given points and a line ax+by+c=0, find the point on the line minimizing total distance to all given points. Uses ternary search (not binary) because the distance function is unimodal (U-shaped), not monotonic.

Tangent Lines Between Convex Polygons

Four tangent lines exist between two non-overlapping convex polygons. Upper tangent algorithm: Start with rightmost point of A and leftmost point of B. While the line crosses either polygon, move the relevant point counterclockwise. Lower tangent: similar, moving clockwise.

Convex Hull

The convex hull is the smallest convex polygon enclosing all given points (like stretching a rubber band around the points).

Jarvis March (Gift Wrapping)

  1. Start with the leftmost point (min x)
  2. From current point p, find point q such that triplet (p, q, r) is counterclockwise for all other points r
  3. Set p = q, repeat until returning to start

Time: O(n·h) where h = number of hull points. Best when h is small.

Graham Scan

Phase 1 — Sort:

  1. Find bottom-most point P₀ (min y, then min x for ties)
  2. Sort remaining points by polar angle counterclockwise around P₀
  3. Remove colinear points except farthest from P₀

Phase 2 — Scan:

  1. Process points one by one. Track last three: prev, curr, next
  2. If orientation(prev, curr, next) is NOT counterclockwise → discard curr (it makes a right turn)
  3. Else keep curr. Continue until all processed.

Time: O(n log n) (dominated by sorting). Better than Jarvis when h is large.

Jarvis vs Graham

Jarvis MarchGraham Scan
TimeO(n·h)O(n log n)
Best whenh ≪ n (few hull points)h ≈ n (many hull points)
ApproachGift wrapping from leftmostSort then scan

Orientation Test (Used by Both Algorithms)

For three points p, q, r, compute the cross product of vectors (q−p) and (r−q):

val = (q.y − p.y)·(r.x − q.x) − (q.x − p.x)·(r.y − q.y)
if val == 0  → Collinear
if val > 0   → Clockwise
if val < 0   → Counterclockwise

Complexity Classes

Key Relationships

  • P ⊆ NP (everything solvable in poly time is also verifiable)
  • The P vs NP question: Is P = NP or P ⊊ NP? (Clay Millennium Prize — $1M)
  • If any NP-Complete problem is solvable in polynomial time, then ALL NP problems are (P = NP)
  • NP-Complete = NP ∩ NP-Hard

Polynomial Reduction

Definition: Problem X reduces to problem Y (X ≤ₚ Y) if an algorithm for Y can be used to solve X in polynomial time.

Instance of X  →  [Polynomial Transform]  →  Algorithm for Y  →  Solution to X

Cost: cost(solving X) = M × cost(solving Y) + cost(reduction)

Two uses:

  • Algorithm design: If we can solve Y, we can solve X too
  • Hardness proof: If X is hard and X ≤ₚ Y, then Y is at least as hard as X

Reduction Example: Sorting ≤ₚ Convex Hull

Given N integers to sort, map each integer xᵢ to point (xᵢ, xᵢ²) on a parabola. The convex hull of these points, traversed in order, gives the sorted sequence. Since sorting is Ω(n log n), convex hull must also be Ω(n log n). Graham scan achieves O(n log n) → optimal.

Proving a Problem is NP-Complete

  1. Show it's in NP: Given a certificate, verify the solution in polynomial time
  2. Show it's NP-Hard: Reduce a known NP-Complete problem to it in polynomial time

Decision vs Optimization Problems

Decision: "Is there a solution with cost ≤ k?" (yes/no). Optimization: "Find the minimum-cost solution." NP-Completeness is defined for decision problems, but if the decision version is hard, the optimization version is at least as hard.

NP-Complete Problems Focus Topic

Sessions 22 & 23

Clique

Problem: Given graph G and integer k, does G contain a complete subgraph (clique) of size k?

Dividing into two cliques: G can be split into two cliques iff the complement of G is bipartite.

  • Step 1: Compute complement graph G'
  • Step 2: Check if G' is bipartite (BFS/DFS 2-coloring)

Vertex Cover

Problem: Given graph G and integer k, is there a subset S of ≤ k vertices such that every edge has at least one endpoint in S?

NP-Complete. No known polynomial solution unless P = NP.

2-Approximation Algorithm

APPROX-VERTEX-COVER(G):
  C = ∅;  E' = E
  while E' ≠ ∅:
    Pick any edge (u,v) from E'
    C = C ∪ {u, v}
    Remove all edges incident to u or v from E'
  return C

Guarantee: Never returns a cover larger than 2× the optimal.

Independent Set

Problem: Largest set of vertices with no edges between them.

Relationship: Independent set in G = Clique in complement G' (and vice versa). Both NP-Complete. Maximum independent set is NP-hard and hard to approximate.

Hamiltonian Cycle

Problem: Does graph G contain a cycle visiting every vertex exactly once?

Naive: Try all n! permutations → O(n!).

Backtracking approach:

  1. Start from vertex 0. Maintain path array.
  2. Before adding vertex: check it's adjacent to last vertex AND not already in path
  3. If stuck, backtrack and try another vertex

Contrast with Shortest Path: Shortest path is in P; Hamiltonian path is NP-Complete.

Traveling Salesman Problem (TSP)

Problem: Find the shortest route visiting every city exactly once and returning to start. Essentially finding the minimum-weight Hamiltonian cycle.

NP-Hard — no known polynomial time solution.

Approaches

MethodTimeNotes
Naive (all permutations)O(n!)Try every starting arrangement
Dynamic ProgrammingO(n²·2ⁿ)Better than naive but still exponential
MST-based ApproximationO(n² or E log V)Requires triangle inequality; ≤ 2× optimal

DP Recurrence

C(S, i) = min over j∈S, j≠i [ C(S−{i}, j) + dist(j, i) ]
Base case: C({1}, 1) = 0
Answer: min over i [ C(V, i) + dist(i, 1) ]

MST-based 2-Approximation (requires triangle inequality)

  1. Build MST from vertex 1 using Prim's algorithm
  2. List vertices in preorder traversal of MST
  3. Add starting vertex at end → this is the tour

Proof of 2× bound:

  • Optimal TSP tour ≥ MST cost (removing one edge from optimal tour gives a spanning tree)
  • Full walk of MST ≤ 2 × MST cost (each edge traversed twice)
  • Preorder walk ≤ full walk (triangle inequality lets us shortcut)
  • Therefore: tour cost ≤ 2 × optimal

NP Quick Reference

  • P: solvable in poly time | NP: verifiable in poly time | NPC: in NP AND NP-Hard
  • Proving NPC: (1) Show in NP (verify in poly time), (2) Reduce known NPC to it
  • Key NPC problems: SAT, 3-SAT, Clique, Vertex Cover, Independent Set, Hamiltonian Cycle, TSP (decision)
  • Approx: Vertex Cover 2×, TSP 2× (with triangle ineq.)
  • Decision vs Optimization: Decision = yes/no; Optimization = find best. If decision is hard, optimization is at least as hard.
